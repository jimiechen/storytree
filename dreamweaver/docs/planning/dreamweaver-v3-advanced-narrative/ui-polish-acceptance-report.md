## 2. 每日同步与问题追踪机制 (Tracking Mechanism)

为了在接下来的服务端功能模块开发中保持高质量交付，已确立以下机制：
1. **状态机驱动 (RALPH_STATE)**: 所有的任务流转统一由 \`RALPH_STATE.md\` 记录。不允许越过当前 Sprint 开启新任务。
2. **测试驱动 (TDD + E2E)**: 所有新功能必须先补充/修改对应的 E2E 测试 (位于 \`tests/e2e/\`)。代码合并的唯一标准是 \`npm run test:e2e\` 全量通过。
3. **每日对齐 (Daily Sync)**: 每次会话结束前，必须输出包含 "任务进度 %", "测试通过率 %", "当前阻塞项" 的标准化报告。

## 三、根因分析

### 为什么做了这么多 Phase 但视觉还是差？

```
原因链:
  PLAN.md 定义了 STDD 流程 (Types→Tests→Mock→Dev→Verify)
       ↓
  每个 Phase 的验收标准只有工程指标 (bun test / typecheck / grep mock-data)
       ↓
  没有"视觉还原"作为通过条件
       ↓
  Agent 把"能跑通"当作"完成"
       ↓
  UI 用 Tailwind 默认值(gray-100/200/500)快速填充
       ↓
  与原型差距越来越大
```

## 四、主控决策请求

请主控裁决以下问题：

### 决策 A: 是否设立"视觉重构冲刺期"？

**方案 A1**: 设立 Phase 1.4 Visual Sprint（推荐）
- 目标: 将 Workspace 从 30% 提升至 80%
- 范围: 仅 `04_小说项目工作台` 一个原型
- 时长: 1 个 Phase
- 交付物: TopAppBar + SideNavBar + 编辑器头部 + 正文排版 + AI 进度浮窗 + 生成面板控件修正
- 不新增任何功能，纯视觉对齐

**方案 A2**: 继续按现有 Phase 推进，每个 Phase 附带视觉修复
- 优点: 不打断功能开发节奏
- 缺点: 视觉债务持续累积，可能永远追不上

### 决策 B: SideNavBar vs Tab 切换器？

原型明确使用 **SideNavBar（竖向导航列表 + 左侧紫色竖线激活态）**，但我们实现的是 **Tab 切换器（横向标签页）**。

这是一个**架构级决策**：
- **跟随原型**: 需要重写 outline-sidebar.tsx，改为竖向导航模式
- **保持 Tab**: 可以解释为"渐进式改进"，但与原型不一致

### 决策 C: 图标系统是否立即引入 Material Symbols？

当前所有图标都是 emoji 或 Unicode 符号（⚡ ⊞ ✓ + ← ✨ 📝 🧭），与原型的 Material Symbols Outlined 差距明显。

引入方式:
- Google Fonts CDN（最快，一行 HTML）
- 本地 SVG icon 组件（最可靠，但工作量大）
- @material/web npm 包（中等）

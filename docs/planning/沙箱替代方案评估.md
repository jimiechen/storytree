## 1. 核心发现：Git Worktree 隔离系统

### 1.1 什么是 Git Worktree

Git Worktree 是 Git 的一个内置功能，允许你在同一个仓库中同时拥有多个工作树（working trees），每个工作树可以：
- 有自己的分支
- 有自己的文件系统视图
- 但共享同一个 `.git` 目录（节省磁盘空间）

### 1.2 Claude Code 中的 Worktree 实现

Claude Code 有一个**完整的、完全开源的 Git Worktree 隔离系统**，位于：
[worktree.ts](file:///workspace/caiode/claude-code-src/utils/worktree.ts)

**核心功能**：

| 功能 | 说明 | 可移植性 |
|------|------|---------|
| createWorktreeForSession | 为会话创建独立的 worktree | ✅ 完全可移植 |
| createAgentWorktree | 为智能体创建独立的 worktree | ✅ 完全可移植 |
| cleanupWorktree | 清理 worktree | ✅ 完全可移植 |
| createTmuxSessionForWorktree | 结合 tmux 进行终端隔离 | ✅ 完全可移植 |

### 1.3 Worktree 隔离的优势

1. **完全开源**：不需要任何私有依赖
2. **Git 原生支持**：稳定、可靠、跨平台
3. **轻量级**：共享同一个 git 仓库，不重复存储文件
4. **分支隔离**：每个 worktree 可以有自己的分支
5. **文件隔离**：每个 worktree 的修改不会影响其他 worktree
6. **自动清理**：支持过期 worktree 的自动清理

## 2. 其他开源隔离机制

### 2.1 InProcessBackend（进程内隔离）

位于：[InProcessBackend.ts](file:///workspace/caiode/claude-code-src/utils/swarm/backends/InProcessBackend.ts)

**隔离方式**：
- 使用 `AsyncLocalStorage` 隔离上下文
- 使用独立的 `AbortController` 控制生命周期
- 使用文件型 mailbox 进行通信

**特点**：
- 同一个进程内运行
- 共享资源（API 客户端、MCP 连接）
- 适合轻量级隔离

### 2.2 Tmux 终端隔离

位于：[worktree.ts](file:///workspace/caiode/claude-code-src/utils/worktree.ts) 的 `createTmuxSessionForWorktree` 函数

**隔离方式**：
- 使用 tmux 创建独立的终端会话
- 每个 worktree 可以在自己的 tmux 会话中运行
- 支持 iTerm2 原生集成

## 四、根因分析

### 4.1 直接原因

```
1. PLAN.md 未将"视觉还原"作为验收标准
   → Agent 只关注 bun test / typecheck 通过
   → UI 用 Tailwind 默认值快速填充

2. 缺少"设计稿对照分析"步骤
   → 每个 Phase 开始前未逐元素对比原型
   → 开发时凭记忆/想象而非对照 PRD

3. 图标系统从未被提及
   → 所有页面用 emoji 替代 Material Symbols
   → 未引入 Google Fonts 图标字体

4. 组件形态理解偏差
   → AI 生成设置应是弹窗(Modal)而非嵌入面板
   → 书架应有 SideNav 而非全屏页
   → 左侧导航应是 SideNavBar 而非 Tab 切换器
```

### 4.2 系统性原因

| 缺失环节 | 影响 | 说明 |
|---------|------|------|
| 无 UI 组件库/设计系统 | 全部 | 每个页面独立写样式，无法复用 |
| 无图标组件封装 | 全部 | 直接写 Unicode/emoji，无法统一替换 |
| 无字体加载配置 | 全部 | `index.html` 未引入 Google Fonts |
| 无截图对比流程 | 全部 | 开发完成后未与原型截图逐项对照 |
| 无视觉验收门禁 | 全部 | 验收只看测试通过，不看 UI 还原度 |

### 决策 1: 是否立即执行 P0 修复？

**方案 A**: 立即执行 P0（推荐）
- 先引入图标+字体（2.5h），解决跨页面共性问题

**方案 B**: 继续推进新功能（Phase 2.x/5.x）
- 优点: 功能覆盖度提升
- 缺点: 视觉债务继续累积，用户体验差

### 决策 2: SideNavBar 模式是否必须？

原型中书架和工作台都有 **SideNav 左侧导航**（深色背景、图标+文字、紫色竖线激活态）。当前实现：
- 书架: 全屏内容页（无 SideNav）
- 工作台: 左侧是 Tab 切换器（非 SideNav）

**请主控裁决**: 是否必须重写为 SideNavBar，还是可以接受 Tab 切换器作为渐进式替代？

### 决策 3: AI 生成设置形态

PRD 10 明确是 **Modal 弹窗**，但当前实现是 **Workspace 右侧面板**。

**请主控裁决**: 
- A) 严格按 PRD 改为弹窗（需要从右侧抽出，改为居中弹窗）
- B) 保持面板形态（可能更符合实际交互效率，但与 PRD 不一致）

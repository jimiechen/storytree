
# 长任务实现分析报告

## 1. 概述

本文档对比分析 Claude Code 和 Opencode 两个项目中长任务的实现方式。

## 2. Claude Code 长任务实现

### 2.1 核心架构

Claude Code 的长任务系统由以下核心部分组成：

#### 2.1.1 任务框架 (`utils/task/framework.ts`)

- **轮询机制**: 1秒间隔轮询任务状态
- **状态管理**: 支持 pending、running、completed、failed、killed 5种状态
- **通知系统**: XML格式的任务通知
- **前台/后台切换**: 支持任务在前台和后台之间切换
- **停滞检测**: Stall watchdog 机制检测任务是否停滞

#### 2.1.2 任务管理 (`utils/tasks.ts`)

- **文件持久化**: 任务状态存储在 JSON 文件中
- **并发控制**: 使用文件锁防止竞态条件
- **高水位标记**: 防止任务 ID 重复使用
- **团队协作**: 支持团队成员任务分配和状态管理

**核心功能**:
- `createTask()`: 创建新任务
- `updateTask()`: 更新任务状态
- `deleteTask()`: 删除任务
- `claimTask()`: 认领任务（支持代理状态检查）
- `listTasks()`: 列出所有任务
- `getAgentStatuses()`: 获取团队成员状态

#### 2.1.3 任务类型 (`tasks/`)

Claude Code 支持 7 种任务类型：

1. **local_bash**: 本地 Shell 任务 ([LocalShellTask/LocalShellTask.tsx](file:///workspace/caiode/claude-code-src/tasks/LocalShellTask/LocalShellTask.tsx))
   - 执行本地命令
   - 支持实时输出流式显示
   - 可被杀死（kill）

2. **local_agent**: 本地代理任务
   - 在本地运行子代理

3. **remote_agent**: 远程代理任务
   - 连接到远程代理

4. **in_process_teammate**: 进程内队友任务
   - 在同一进程中运行的协作代理

5. **local_workflow**: 本地工作流任务
   - 执行工作流脚本

6. **monitor_mcp**: MCP 监控任务
   - 监控 MCP 服务器

7. **dream**: Dream 任务 ([DreamTask/DreamTask.ts](file:///workspace/caiode/claude-code-src/tasks/DreamTask/DreamTask.ts))
   - 自动记忆整合子代理
   - 用于后台记忆处理

### 2.3 实现特点

1. **磁盘持久化**: 所有任务状态都保存到磁盘
2. **多进程协作**: 通过文件锁支持多 Claude 实例协作
3. **团队功能**: 支持任务分配、状态跟踪、代理忙闲检查
4. **任务依赖**: 支持任务之间的阻塞关系
5. **完整的任务生命周期**: 创建 → 认领 → 执行 → 完成 → 失败

## 3. Opencode 长任务实现

### 3.1 核心架构

Opencode 的任务系统基于 Effect 生态系统构建：

#### 3.1.1 Task 工具 ([tool/task.ts](file:///workspace/caiode/opencode/packages/opencode/src/tool/task.ts))

- **子代理会话管理**: 创建和恢复子代理会话
- **权限控制**: 子代理权限继承和限制
- **任务恢复**: 支持通过 task_id 恢复之前的任务

**核心功能**:
- 创建子代理会话
- 执行子代理任务
- 任务恢复（通过 task_id）
- 权限过滤和继承

#### 3.1.2 Todo 系统 ([session/todo.ts](file:///workspace/caiode/opencode/packages/opencode/src/session/todo.ts))

- **数据库持久化**: 使用 SQLite 存储待办事项
- **Event Bus**: 通过 Bus 系统广播待办更新事件
- **Effect 服务**: 基于 Effect 框架的服务层

**核心功能**:
- `Todo.update()`: 更新待办列表
- `Todo.get()`: 获取待办列表
- 事件驱动的更新通知

#### 3.1.3 TodoWrite 工具 ([tool/todo.ts](file:///workspace/caiode/opencode/packages/opencode/src/tool/todo.ts))

- **待办管理**: 通过工具接口管理待办事项
- **权限检查**: 验证 todowrite 权限

### 3.2 关键文件

| 文件路径 | 说明 |
|---------|------|
| [tool/task.ts](file:///workspace/caiode/opencode/packages/opencode/src/tool/task.ts) | Task 工具实现 |
| [session/todo.ts](file:///workspace/caiode/opencode/packages/opencode/src/session/todo.ts) | Todo 系统实现 |
| [tool/todo.ts](file:///workspace/caiode/opencode/packages/opencode/src/tool/todo.ts) | TodoWrite 工具实现 |

### 3.3 实现特点

1. **Effect 生态**: 基于 Effect 框架，提供强大的错误处理和依赖注入
2. **会话隔离**: 子代理有独立的会话 ID
3. **权限继承**: 子代理权限可配置继承和限制
4. **数据库存储**: Todo 数据存储在 SQLite 中
5. **事件驱动**: 通过 Bus 系统广播更新事件

## 4. 对比分析

| 维度 | Claude Code | Opencode |
|-----|-------------|---------|
| **任务类型** | 7种（local_bash、local_agent、remote_agent、in_process_teammate、local_workflow、monitor_mcp、dream） | 主要是子代理任务 + Todo 管理 |
| **持久化方式** | JSON 文件 | SQLite 数据库 |
| **状态管理** | 5种状态（pending、running、completed、failed、killed） | Todo 有 4种状态（pending、in_progress、completed、cancelled） |
| **并发控制** | 文件锁 | Effect 事务 + 数据库事务 |
| **多进程协作** | 完整支持 | 基于数据库的协作 |
| **团队功能** | 任务分配、代理状态管理 | Todo 列表共享 |
| **任务恢复** | 高水位标记防重复 | 通过 task_id 恢复会话 |
| **技术栈** | 原生 TypeScript + 文件系统 | Effect 生态系统 + SQLite |

## 5. 总结

### Claude Code 优势
- 更丰富的任务类型支持
- 完善的多进程协作机制
- 强大的团队任务管理功能
- 成熟的任务生命周期管理

### Opencode 优势
- 现代化的 Effect 框架
- 数据库级别的事务支持
- 简洁的子代理会话管理
- 事件驱动的架构

### 移植建议
对于我们的项目，可以考虑：
1. 采用 Claude Code 的任务类型设计
2. 借鉴 Opencode 的 Effect 架构模式
3. 结合两者的持久化策略（文件 + 数据库混合）
4. 保留 Claude Code 的团队协作功能

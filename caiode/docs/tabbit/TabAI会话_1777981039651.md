### **二、Week 1 MVP 产品原型清单**

下面这份清单可以直接放进 `WEEK1-MVP-PRODUCT-PROTOTYPE-CHECKLIST.md`。

```markdown
# Week 1：AI 小说编辑器 MVP 产品原型清单

## 一、MVP 原型目标

本阶段目标不是完成真实 AI 接入，也不是完成完整小说创作平台，而是基于 Mock 数据和 FakeAgentProvider，验证 AI 小说编辑器的最小产品闭环。

MVP 需要验证的核心链路是：

用户打开小说项目 → 查看项目结构 → 选择章节 → 编辑正文 → 查看角色卡与世界观信息 → 发起 AI 续写/改写/摘要任务 → FakeAgentProvider 返回模拟结果 → 用户采纳或丢弃 → 系统记录 AITask 与 AILog。

## 二、MVP 原型范围

### 1. 必须包含的页面

| 页面 | 是否必须 | 说明 |
|---|---:|---|
| 小说项目首页 / 工作台 | 必须 | 展示当前小说项目、章节列表、角色列表、AI 任务状态 |
| 章节编辑器页面 | 必须 | 支持正文编辑、章节大纲、AI 建议结果展示 |
| 角色卡页面 / 侧栏 | 必须 | 展示角色设定、性格、关系、口吻 |
| AI 任务面板 | 必须 | 支持续写、改写、摘要、角色语气改写等 Mock 任务 |
| AI 日志页面 / 抽屉 | 必须 | 展示任务输入、输出、状态、时间、错误信息 |
| 设置页 | 可选 | 仅展示 Mock 模式开关，不接真实模型 |

### 2. 必须包含的核心组件

| 组件 | 是否必须 | 说明 |
|---|---:|---|
| ProjectHeader | 必须 | 展示项目名、类型、字数、更新时间 |
| ChapterList | 必须 | 展示章节列表、章节状态、字数 |
| ChapterEditor | 必须 | 主编辑区，用于章节正文编辑 |
| OutlinePanel | 必须 | 展示章节目标、冲突、关键剧情点 |
| CharacterPanel | 必须 | 展示角色卡和角色关系 |
| AITaskPanel | 必须 | 发起 AI Mock 任务 |
| AIResultCard | 必须 | 展示 AI 返回结果，支持采纳/丢弃 |
| AITaskStatusBadge | 必须 | 展示 pending/running/success/failed/cancelled |
| AILogDrawer | 必须 | 展示任务日志 |
| MockModeBanner | 必须 | 明确当前为 Mock 模式，不调用真实模型 |

### 3. 必须包含的业务对象

| 对象 | 是否必须 | 说明 |
|---|---:|---|
| Project | 必须 | 小说项目 |
| Sandbox | 必须 | 创作沙箱 / 世界观空间 |
| Chapter | 必须 | 章节 |
| Character | 必须 | 角色 |
| AITask | 必须 | AI 任务状态 |
| AILog | 必须 | AI 调用日志 / Mock 日志 |

## 三、MVP 用户流程

### 流程 1：打开小说项目

用户进入工作台后，可以看到当前小说项目，包括项目名称、题材、简介、总字数、更新时间、章节数量、角色数量和当前 Mock 模式提示。

通过标准：

- 能看到至少 1 个 Mock 项目。
- 能看到项目基本信息。
- 能看到 Mock 模式提示。
- 不出现真实模型配置入口。

### 流程 2：选择章节并编辑

用户从章节列表中选择一个章节，进入章节编辑区。编辑区展示章节标题、章节正文、章节目标和剧情要点。

通过标准：

- 能看到至少 3 个 Mock 章节。
- 能切换章节。
- 能编辑当前章节正文。
- 能看到章节大纲和剧情目标。

### 流程 3：查看角色卡

用户在编辑章节时，可以在右侧面板查看相关角色卡，包括角色姓名、身份、性格、目标、秘密、口吻和与其他角色的关系。

通过标准：

- 能看到至少 3 个 Mock 角色。
- 能查看角色基本信息。
- 能查看角色口吻设定。
- 能查看角色关系。

### 流程 4：发起 AI Mock 任务

用户可以在 AI 任务面板选择任务类型，包括续写、改写、摘要、角色语气改写。点击执行后，系统创建 AITask，并由 FakeAgentProvider 返回模拟结果。

通过标准：

- 支持续写任务。
- 支持改写任务。
- 支持摘要任务。
- 支持角色语气改写任务。
- 任务状态从 pending → running → success。
- 不调用真实模型。
- 不调用真实 Agent。
- 不访问外部网络。

### 流程 5：采纳或丢弃 AI 结果

AI 返回结果后，用户可以选择采纳结果，将内容写入章节草稿或建议区；也可以丢弃结果。

通过标准：

- AI 结果以卡片形式展示。
- 支持“采纳到正文”。
- 支持“保存到建议区”。
- 支持“丢弃结果”。
- 操作后 AILog 有记录。

### 流程 6：查看 AI 日志

用户可以打开 AI 日志抽屉或页面，查看历史任务，包括任务类型、输入摘要、输出摘要、状态、耗时、错误原因。

通过标准：

- 能看到任务列表。
- 能看到 success/failed/cancelled 等状态。
- 能看到 Mock 输出内容。
- 能看到错误模拟记录。
- 明确标识 Mock 模式。

## 四、必须覆盖的状态

| 状态 | 是否必须 | 展示方式 |
|---|---:|---|
| 空项目状态 | 必须 | 展示创建项目提示 |
| 加载中状态 | 必须 | Skeleton 或 Loading |
| AI 任务等待中 | 必须 | pending badge |
| AI 任务运行中 | 必须 | running badge + 进度提示 |
| AI 任务成功 | 必须 | success badge + 结果卡片 |
| AI 任务失败 | 必须 | failed badge + 错误信息 |
| AI 任务取消 | 必须 | cancelled badge |
| 权限拒绝 | 必须 | permission_denied 错误提示 |
| 配额不足 | 必须 | quota_exceeded 错误提示 |
| Mock 模式 | 必须 | 顶部 Banner 或角标 |

## 五、MVP 原型验收标准

Week 1 MVP 原型通过标准：

1. 至少完成一个小说项目工作台原型。
2. 至少完成一个章节编辑器原型。
3. 至少完成一个角色卡 / 角色面板原型。
4. 至少完成一个 AI 任务面板原型。
5. 至少完成一个 AI 日志抽屉或日志页面原型。
6. 原型中明确显示 Mock Mode。
7. 原型中不出现真实 API Key 配置。
8. 原型中不出现真实模型调用入口。
9. 原型中不出现 Bash、WebFetch、WebSearch、Agent、Task 等高权限工具入口。
10. 原型能表达完整的 Mock 闭环：输入 → 任务 → 结果 → 采纳 → 日志。
```

### **四、Stitch MVP 产品原型总提示词**

#### **1. 总体 MVP App 原型提示词**

```text
Design a desktop-first MVP prototype for an AI novel editor called “Card Story Novel Studio”.

The app is in Mock Mode only. It does not connect to real AI models, real agents, API keys, command execution, web search, or external tools.

The product helps a novelist manage a fiction project, edit chapters, view character cards, and run simulated AI writing tasks through a FakeAgentProvider.

Create a clean, modern, professional writing workspace with the following main areas:

1. A top project header showing project name, genre, word count, last updated time, and a visible “Mock Mode” badge.
2. A left sidebar with chapter list, chapter status, word count, and selected chapter highlight.
3. A central chapter editor with title, outline, main writing area, and AI suggestion result cards.
4. A right sidebar with character cards, world setting notes, and relationship hints.
5. A bottom or right AI task panel with buttons for “Continue Writing”, “Rewrite”, “Summarize”, and “Rewrite in Character Voice”.
6. An AI task log drawer showing task status: pending, running, success, failed, cancelled, permission_denied, and quota_exceeded.
7. Clear actions for “Accept AI Result”, “Save to Suggestions”, and “Discard”.

Use a calm creative writing style, with soft neutral backgrounds, readable typography, subtle borders, and a focused editor-first layout. The interface should feel like a professional writing tool, not a chatbot.

Do not include real model settings, API key fields, command execution tools, web search, terminal panels, plugin marketplace, billing, or deployment settings.
```

## **一、为什么不能用普通 Playwright 写**

普通 E2E 测 3D 交互有三个坑，在动手前必须先解决，否则跑出来的红绿都不可信。

**第一个坑：Three.js Canvas 是 WebGL 像素**，Playwright 的 locator 抓不到光源、长方体这种"逻辑对象"。`page.locator('canvas').click()` 只能点到画布像素，没法表达"点击 box-3"。解决办法是在 ThreeViewport mount 时挂一个调试桥到 `window`：

```ts
// ThreeViewport.tsx 仅在 process.env.NODE_ENV !== 'production' 时挂载
if (typeof window !== 'undefined' && import.meta.env.MODE !== 'production') {
  (window as any).__shot3d = {
    store: props.store,
    managers: { cyl: cylManager, box: boxManager, light: lightManager },
    groupCtrl,
    transformCtx,
    // 拿对象在屏幕上的像素坐标，用于驱动鼠标
    projectToScreen: (id: string) => {
      const entry = 
        cylManager.findById(id) ?? 
        boxManager.findById(id) ?? 
        lightManager.findById(id);
      if (!entry) return null;
      const v = new THREE.Vector3();
      entry.obj.getWorldPosition(v);
      v.project(camera);
      const rect = canvas.getBoundingClientRect();
      return {
        x: rect.left + (v.x + 1) / 2 * rect.width,
        y: rect.top + (1 - v.y) / 2 * rect.height,
      };
    },
    // 直接读 mesh 的世界 transform，绕过 store
    readMeshTransform: (id: string) => { /* ... */ },
    // 测试用快捷入口（绕过 UI）
    test: {
      addBoxArray: () => { /* 一键加 4 box 编组 */ },
      selectById: (id: string) => props.store.selectAny(id),
      getStoreSnapshot: () => JSON.parse(JSON.stringify(props.store.scene)),
      getDraggingState: () => props.store.scene.__dragging ?? null,
      getLogs: () => (window as any).__shot3dLogs ?? [],
    },
  };
}
```

**第二个坑：TransformControls 的 gizmo 需要"先点中再拖"**，普通 click 拿不到 gizmo 的轴。所以测试要用 `page.mouse.move → mouse.down → 多次 mouse.move → mouse.up` 三段式，配合 `projectToScreen` 把世界坐标换算到像素。

**第三个坑：失焦跳回是"事件顺序竞态"，必须按帧截图**，不能只截首尾。VRT（视觉回归）的关键是录视频 + 关键帧截图 + 像素差比对。Playwright 自带 `recordVideo` + `expect(page).toHaveScreenshot()` 两件套。

## **三、测试用例的"探针 + 断言"双轨设计**

每个用例都有两条独立的证据链，都通过才算 PASS。

```text
探针轨（白盒）：通过 __shot3d 桥读 mesh.position / store.scene
  → 优点：精确到 1e-4，不受像素抖动影响
  → 用途：判断"是不是真的回弹了"

视觉轨（黑盒）：录视频 + 关键帧截图 + 像素差比对
  → 优点：能看到 gizmo 是否绑对、是否闪烁
  → 用途：作为给人看的验收凭证（demo 里能放）
```

### **3.1 用例 1：光源失焦不跳回（核心）**

```ts
test('light-defocus does not snap back', async ({ page }, testInfo) => {
  await page.goto('/shot3d');
  await ensureBridge(page);

  // === 步骤 1：添加光源 ===
  await page.evaluate(() => window.__shot3d.test.addLight({ x: 0, y: 1.5, z: 0 }));
  const lightId = await page.evaluate(() => 
    window.__shot3d.store.scene.lights[0].id
  );

  await page.evaluate((id) => window.__shot3d.test.selectById(id), lightId);
  await page.screenshot({ path: testInfo.outputPath('01-selected.png') });

  // === 步骤 2：拖拽光源到 (3, 1.5, 2) ===
  await dragGizmoTo(page, lightId, { x: 3, y: 1.5, z: 2 });
  await page.waitForTimeout(100);
  await page.screenshot({ path: testInfo.outputPath('02-after-drag.png') });

  // 探针断言 A：拖拽后 store 已同步
  const afterDrag = await page.evaluate((id) => 
    window.__shot3d.test.getStoreSnapshot().lights.find(l => l.id === id)
  , lightId);
  expect(afterDrag.position.x).toBeCloseTo(3, 1);
  expect(afterDrag.position.z).toBeCloseTo(2, 1);

  // === 步骤 3：点击空白处失焦（关键操作）===
  // 在画布远离任何对象的位置点一下
  const canvas = page.locator('canvas').first();
  const box = await canvas.boundingBox();
  await page.mouse.click(box.x + 50, box.y + 50);

  // 等 3 帧（约 50ms），让所有 Effect 跑完
  await page.evaluate(() => new Promise(r => 
    requestAnimationFrame(() => requestAnimationFrame(() => requestAnimationFrame(r)))
  ));
  await page.screenshot({ path: testInfo.outputPath('03-after-defocus.png') });

  // === 探针断言 B：mesh 位置必须保持 ===
  const meshAfterDefocus = await page.evaluate((id) => 
    window.__shot3d.test.readMeshTransform(id)
  , lightId);
  expect(meshAfterDefocus.position.x).toBeCloseTo(3, 1);
  expect(meshAfterDefocus.position.y).toBeCloseTo(1.5, 1);
  expect(meshAfterDefocus.position.z).toBeCloseTo(2, 1);

  // === 探针断言 C：store 也保持 ===
  const storeAfterDefocus = await page.evaluate((id) => 
    window.__shot3d.test.getStoreSnapshot().lights.find(l => l.id === id)
  , lightId);
  expect(storeAfterDefocus.position.x).toBeCloseTo(3, 1);

  // === 探针断言 D：日志中没有"被 update 覆盖"的痕迹 ===
  const logs = await page.evaluate(() => window.__shot3d.test.getLogs());
  const overwriteLog = logs.find(l => 
    l.tag === 'lightUpdate' && 
    l.id === lightId && 
    Math.abs(l.storePos.x) < 0.01 &&  // store 里是旧值 0
    !l.skipped                          // 但没被 dragging 锁拦下
  );
  expect(overwriteLog, '检测到 update 用旧 position 覆盖 mesh').toBeUndefined();

  // === 视觉轨：02 与 03 帧应该几乎一致 ===
  await expect(page).toHaveScreenshot('light-defocus-stable.png', {
    maxDiffPixelRatio: 0.02,
  });
});
```

```ts
test('box-array moves as a whole', async ({ page }, testInfo) => {
  await page.goto('/shot3d');
  await ensureBridge(page);

  // 一键创建 4 box 方阵
  await page.evaluate(() => window.__shot3d.test.addBoxArray());

  // 探针断言 A：4 个 box 有同一个 groupId
  const groupIds = await page.evaluate(() => 
    window.__shot3d.test.getStoreSnapshot().boxes.map(b => b.groupId)
  );
  expect(new Set(groupIds).size).toBe(1);
  expect(groupIds[0]).toBeTruthy();

  // 选中第一个 box
  const firstId = await page.evaluate(() => 
    window.__shot3d.store.scene.boxes[0].id
  );
  await page.evaluate((id) => window.__shot3d.test.selectById(id), firstId);

  // 探针断言 B：selectedGroupId 已同步
  const selected = await page.evaluate(() => ({
    objectId: window.__shot3d.store.scene.selectedObjectId,
    groupId: window.__shot3d.store.scene.selectedGroupId,
  }));
  expect(selected.groupId).toBe(groupIds[0]);

  // 探针断言 C：TransformControls 绑定的是 group-helper
  const attached = await page.evaluate(() => {
    const obj = window.__shot3d.transformCtx.getControls().object;
    return obj ? { role: obj.userData?.role, groupId: obj.userData?.groupId } : null;
  });
  expect(attached?.role).toBe('group-helper');
  expect(attached?.groupId).toBe(groupIds[0]);

  await page.screenshot({ path: testInfo.outputPath('01-array-selected.png') });

  // 记录拖前 4 个 box 位置
  const beforeDrag = await page.evaluate(() => 
    window.__shot3d.test.getStoreSnapshot().boxes.map(b => ({
      id: b.id,
      position: { ...b.position },
    }))
  );

  // 拖动 helper 沿 X 轴 +2
  await dragGroupGizmo(page, groupIds[0], { dx: 2, dy: 0, dz: 0 });
  await page.waitForTimeout(150);

  // 探针断言 D：4 个 box 全部 +2
  const afterDrag = await page.evaluate(() => 
    window.__shot3d.test.getStoreSnapshot().boxes
  );
  for (const before of beforeDrag) {
    const after = afterDrag.find(b => b.id === before.id);
    expect(after.position.x - before.position.x).toBeCloseTo(2, 1);
    expect(after.position.y - before.position.y).toBeCloseTo(0, 1);
    expect(after.position.z - before.position.z).toBeCloseTo(0, 1);
  }

  await page.screenshot({ path: testInfo.outputPath('02-array-moved.png') });

  // 探针断言 E：松手后 helper 重新落在新重心
  const helperPos = await page.evaluate(() => {
    const obj = window.__shot3d.transformCtx.getControls().object;
    return obj ? { x: obj.position.x, y: obj.position.y, z: obj.position.z } : null;
  });
  const center = afterDrag.reduce((acc, b) => ({
    x: acc.x + b.position.x / 4,
    y: acc.y + b.position.y / 4,
    z: acc.z + b.position.z / 4,
  }), { x: 0, y: 0, z: 0 });
  expect(helperPos.x).toBeCloseTo(center.x, 1);
});
```

## **四、关键工具函数**

### **4.1 `dragGizmoTo` —— 单体拖拽**

```ts
// lib/transform-driver.ts
export async function dragGizmoTo(
  page: Page, 
  objectId: string, 
  target: { x: number; y: number; z: number }
) {
  // 1. 拿对象当前屏幕坐标
  const start = await page.evaluate((id) => 
    window.__shot3d.projectToScreen(id), objectId
  );
  // 2. 拿目标位置的屏幕坐标
  const end = await page.evaluate((tgt) => {
    const v = new THREE.Vector3(tgt.x, tgt.y, tgt.z);
    v.project(window.__shot3d.camera);
    const rect = window.__shot3d.canvas.getBoundingClientRect();
    return {
      x: rect.left + (v.x + 1) / 2 * rect.width,
      y: rect.top + (1 - v.y) / 2 * rect.height,
    };
  }, target);

  // 3. 鼠标三段式
  await page.mouse.move(start.x, start.y);
  await page.mouse.down();
  // 中间分段移动，模拟真实拖拽（让 objectChange 多次触发）
  const steps = 10;
  for (let i = 1; i <= steps; i++) {
    await page.mouse.move(
      start.x + (end.x - start.x) * (i / steps),
      start.y + (end.y - start.y) * (i / steps),
      { steps: 1 }
    );
    await page.waitForTimeout(16);
  }
  await page.mouse.up();
}
```

> **重要提醒**：这个函数对 TransformControls 的"自由拖拽"场景够用，但如果 gizmo 需要先点中某根轴，需要先调用 `__shot3d.test.engageAxis('x' | 'y' | 'z')` 主动激活 X/Y/Z handle。建议在 debug bridge 里直接暴露 `setObjectPosition(id, target)` 一步到位的方法做单元级测试，再用 mouse 模拟做完整链路测试。

```ts
export async function dragGroupGizmo(
  page, 
  groupId: string, 
  delta: { dx: number; dy: number; dz: number }
) {
  const startWorld = await page.evaluate((gid) => {
    const helper = window.__shot3d.groupCtrl.getHelper(gid);
    return helper ? { x: helper.position.x, y: helper.position.y, z: helper.position.z } : null;
  }, groupId);
  
  const startScreen = await page.evaluate((world) => {
    const v = new THREE.Vector3(world.x, world.y, world.z).project(window.__shot3d.camera);
    const rect = window.__shot3d.canvas.getBoundingClientRect();
    return {
      x: rect.left + (v.x + 1) / 2 * rect.width,
      y: rect.top + (1 - v.y) / 2 * rect.height,
    };
  }, startWorld);

  const endScreen = await page.evaluate(({ start, delta }) => {
    const v = new THREE.Vector3(start.x + delta.dx, start.y + delta.dy, start.z + delta.dz)
      .project(window.__shot3d.camera);
    const rect = window.__shot3d.canvas.getBoundingClientRect();
    return {
      x: rect.left + (v.x + 1) / 2 * rect.width,
      y: rect.top + (1 - v.y) / 2 * rect.height,
    };
  }, { start: startWorld, delta });

  await page.mouse.move(startScreen.x, startScreen.y);
  await page.mouse.down();
  for (let i = 1; i <= 10; i++) {
    await page.mouse.move(
      startScreen.x + (endScreen.x - startScreen.x) * (i / 10),
      startScreen.y + (endScreen.y - startScreen.y) * (i / 10),
    );
    await page.waitForTimeout(16);
  }
  await page.mouse.up();
}
```

## **六、三个落地建议**

第一个建议是 **bridge 优先做单元级测试，再做 mouse 模拟**。`__shot3d.test.setObjectPosition(id, target)` 这种 API 能让你跳过 gizmo 像素拾取的不确定性，先用 10 个用例验证"store + manager + Effect"这条逻辑链；等逻辑链稳了再加 5 个 mouse 模拟用例验证"鼠标 → gizmo → store"的物理链。两层都通过才算真正可用。否则一旦相机角度变了，所有 mouse 用例就全红，根本看不出是逻辑出错还是相机出错。

第二个建议是 **基线截图必须提交**。Playwright VRT 的核心是 `snapshots/` 目录里的 PNG，第一次跑用 `--update-snapshots` 生成，之后每次 PR 跑都和它比对。这个目录千万不能加 `.gitignore`，否则 CI 上每次都重新生成基线，VRT 等于废了。

第三个建议是 **把这个 skill 接到 GitHub Actions 的 PR 检查里**。从你的项目结构看，已经有 `.github/workflows/playwright-vrt.yml`，把这个 skill 的入口加上去，每次 PR 改 `novel-3d/` 目录都自动跑这套测试。这样后续任何人改 ThreeViewport 都不会偷偷把这两个 bug 引回来——这是把"修过的 bug"变成"永久不会再出现的 bug"的唯一办法。

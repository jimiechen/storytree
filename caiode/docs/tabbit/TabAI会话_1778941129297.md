## **一、对“阻塞性问题”的答复**

### **阻塞性问题 1：Store 缺少 `boxes` 数组**

评审认为这是阻塞，并给出两条路：

```text
方案 A：保持现有单 cylinders 数组，用 ID 前缀区分 box / light（评审推荐）
方案 B：拆分为 cylinders / boxes / lights 三个数组（原方案）
```

**回应：必须采用方案 B（三数组），不接受单数组兼容方案。**

理由：

第一，**类型安全是这套架构的根本前提**。LightObject 需要 `rotation`、`color`、`intensity`、`range`、`angleDeg`，BoxObject 有 `width / height / depth`，CylinderObject 有 `radius / height`。如果塞进同一个数组，要么用联合类型每次 narrow，要么改成 `any`。前者啰嗦，后者会让后面 3D Shot Draft 插件全线退化为弱类型，得不偿失。

第二，**“ID 前缀区分类型”是反模式**。一旦走上这条路，意味着每个消费方都要写：

```ts
if (id.startsWith('cyl-')) { ... }
else if (id.startsWith('box-')) { ... }
else if (id.startsWith('light-')) { ... }
```

随便加一类对象（相机、角色、道具），全项目都得改。这跟你后面要做的 Storyboard / Camera / Asset 体系完全冲突。

第三，**评审方所说的“当前 Box 复用 cylinders 数组”本身就是历史债务**，不是要去保护的现状。本次刚好是清理它的最佳时机：light 加进来之前一次性把 box 拆出去，比将来再拆代价低得多。

第四，**改动量评审方高估了**。Box 当前如果真是塞在 cylinders 数组里，受影响的只有：

```text
shot-3d-store.ts 的 addBox / updateBox / removeBox
ShapeToolbar 的 box 按钮
ThreeViewport 里 cylinder-manager 处理 box 的分支（如果有）
```

这三处加起来不到 100 行，半小时内能拆干净。

**结论**：方案 B 落地，单数组兼容路径直接放弃。

### **阻塞性问题 2：`selectAny` 函数签名不匹配**

评审给出的所谓“兼容修复”是把 selectAny 内部逻辑改回只操作 cylinders：

```ts
return {
  ...prev,
  selectedObjectId: id,
  cylinders: prev.cylinders.map(c => ({ ...c, selected: c.id === id }))
};
```

**回应：拒绝这个修法。selectAny 必须同时操作三个数组。**

原因很直接：上一轮已经定下来三数组方案，这一条“阻塞”是评审方在“假设采用方案 A”的前提下推导出来的。前提一旦改回方案 B，这条阻塞自动消失。

最终 selectAny 应该就是原方案那一版：

```ts
const selectAny = (id: string | undefined) => {
  if (scene.selectedObjectId === id) return;     // 幂等，避免无效 effect
  setScene(s => ({
    ...s,
    selectedObjectId: id,
    cylinders: s.cylinders.map(c => ({ ...c, selected: c.id === id })),
    boxes:     s.boxes.map(b => ({ ...b, selected: b.id === id })),
    lights:    s.lights.map(l => ({ ...l, selected: l.id === id })),
  }));
};
```

并把 `selectCylinder` / `selectBox` 全部 **改为内部调用 `selectAny`**，不要做“向后兼容的双轨制”。双轨制只会让后面定位 bug 时不知道用户选中状态到底由哪条路径写入。

```ts
const selectCylinder = (id: string | undefined) => selectAny(id);
const selectBox      = (id: string | undefined) => selectAny(id);
const selectLight    = (id: string | undefined) => selectAny(id);
```

这三个外壳保留是为了**调用点**的迁移成本最低，但内部统一收口到 selectAny。

## **二、对“需要关注项”的逐条答复**

### **关注项 1：Effect 1 依赖膨胀，theme 变化触发三类 manager 重跑**

评审建议：拆成两个 effect，仅 light 受 theme 影响。

**采纳，但修法和评审给的略有不同**。

评审方案的写法在 `setScene` 大幅度更新时会出现两次 lightManager.update（一次随 lights 变，一次随 theme 变），反而抖动。更稳的做法是：

```ts
// Effect 1：只同步 mesh 数据，不读 theme
createEffect(on(
  () => [
    props.store.scene.cylinders,
    props.store.scene.boxes,
    props.store.scene.lights,
    props.store.scene.selectedObjectId,
  ] as const,
  ([cylinders, boxes, lights, selectedId]) => {
    cylManager.update(cylinders, selectedId);
    boxManager.update(boxes, selectedId);
    lightManager.update(lights, selectedId);   // 不传 theme
  }
));

// Effect 3：只同步主题视觉
createEffect(on(
  () => props.store.scene.theme,
  (theme) => {
    themeCtrl.apply(theme);
    lightManager.applyTheme(theme);            // 仅刷新 light 材质 opacity / dashSize
  }
));
```

`lightManager` 增加一个轻量的 `applyTheme(theme)`，遍历 visualMap 只改 `material.opacity` 和 `material.needsUpdate`，**不重建 mesh，不重新 setEntries**。这样 theme 切换不会触发 Effect 2 的 TransformControls 重新 attach。

theme 这条线和 mesh 数据线彻底解耦，比评审给的版本更干净。

### **关注项 2：onObjectChange 分发逻辑复杂度**

评审建议：抽成工厂函数 `createObjectChangeHandler(store)`，用 switch-case。

**采纳**。这条没有争议，按评审给的写法落地即可：

```ts
const createObjectChangeHandler = (store: Shot3DStore) => (obj: THREE.Object3D) => {
  const id = obj.userData?.id as string | undefined;
  const kind = obj.userData?.kind as string | undefined;
  if (!id || !kind) return;

  const pos = { x: obj.position.x, y: obj.position.y, z: obj.position.z };

  switch (kind) {
    case 'cylinder': {
      const height = (obj.userData.height ?? 0) as number;
      store.updateCylinder(id, { position: { ...pos, y: pos.y - height / 2 } });
      break;
    }
    case 'box':
      store.updateBox(id, { position: pos });
      break;
    case 'light':
      store.updateLight(id, {
        position: pos,
        rotation: { x: obj.rotation.x, y: obj.rotation.y, z: obj.rotation.z },
      });
      break;
  }
};
```

但要在 `transform-controls-setup.ts` 里把这个 handler 接入 `controls.addEventListener('objectChange', ...)`，并配合上一轮修复加的 requestAnimationFrame 节流。

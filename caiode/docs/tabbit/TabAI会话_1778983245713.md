### **光源失焦还原是因为 store 在失焦那一刻被 selectAny 重置高亮触发了响应式回流，manager.update() 用 store 里"拖拽中根本没写回"的旧 position 把 mesh 拍回原点；方阵失控是因为 ShapeToolbar 加方阵时没真正写 groupId、selectAny 也没同步 selectedGroupId、Effect 2 没读 selectedGroupId 这条链条断了三处——只修一处都不够。下面把两个问题的真因彻底拆开，给 Trae 一份能一次跑通的指导。**

## **一、光源失焦还原的真正机制（比之前判断的更隐蔽）**

你说"圆柱体和长方体移动缩放正常，光源移动也正常，只有光源失焦后跳回去"。这条线索非常关键，它告诉我们：

```text
拖拽期间所有对象表现一致 → objectChange 写回路径没问题
失焦那一刻只有光源跳回 → 问题出在"光源 entry 与 store 数据的同步路径"
```

光源比圆柱/长方体多一层结构：

```text
圆柱体 / 长方体：
  Mesh（geometry 中心 = 原点）
  TransformControls 直接绑 Mesh
  objectChange 写回 mesh.position → store
  manager.update() 读 store.position → mesh.position
  路径完全对称，没有歧义

光源：
  Group(root)
    ├─ LineSegments(虚线圆锥，geometry 已 translate(0, -range/2, 0))
    └─ Mesh(bulb 小球)
  TransformControls 绑 root（Group）
  objectChange 写回 root.position → store.lights[i].position
  manager.update() 读 store.lights[i].position → root.position
  
  但 root 本身是新建的 Group，root.position 和 light.position 在你的当前实现里
  可能不是 1:1 对应——很多实现会在 build 时给 root.position 设成 light.position，
  然后 LineSegments 的 geometry.translate 让锥尖落在 root.position。
  这层"build 时的初始坐标偏移"在 manager.update() 重跑时如果没保持幂等，就会
  在失焦回流那一帧重新走一遍 build 流程，把已经被用户拖到新位置的 root 干回去。
```

也就是说，光源最容易出问题不是因为 dragging 锁，而是因为**它的 root 在 manager.update() 里可能被"重建或重置"了一次**。

### **1.1 三个并存的诱因，必须同时排查**

诱因 A：**update() 没用 Map<id, entry> 增量 diff，而是每次清空重建**

```text
症状：失焦那一帧整个 LightGroup.children 被清空 + 重建
表现：拖到的位置丢失，回到 store 里的旧值
```

诱因 B：**update() 走增量 diff，但 root.position 被无条件 set 回 store.position**

```text
症状：哪怕 epsilon 保护都救不了
原因：失焦前一刻 store.lights[i].position 还是 (0, 1.5, 0)（拖拽期间没写回）
     失焦那一刻 selectAny(undefined) 改了 selected 字段 → 触发响应式
     update() 重跑 → 看到 store.position 还是旧值 → set 回去
```

诱因 C：**objectChange 在拖拽中没把 root.position 实时写回 store**

```text
症状：松手前 store.lights[i].position 完全没变
原因：transform-controls-setup 里只有 dragging-changed=false 时才写回，
     而失焦在写回之前就发生了（你点空白的瞬间 = mouseup → dragging-changed=false → 失焦）
     这两个事件的顺序如果颠倒，就会出现"先失焦再写回"或"先失焦再被覆盖"的竞态
```

**最可能的真因是 B + C 的组合**：你松开鼠标的那一帧，Three.js 的 dragging-changed 和你的 click-empty 失焦逻辑几乎同时触发，顺序无法保证。如果 click-empty 先到，selectAny(undefined) 就会先触发 Effect 2 重跑，而此时 store 还没收到 dragging-changed=false 的写回，update() 看到的是旧 position，光源就被拍回去了。

圆柱和长方体不出现这个问题，是因为它们的 `mesh.position` 即使被 update() set 一次，set 的值仍然是用户拖到的位置（如果 store 里已经写回了）。但光源因为某种原因 store 没及时更新——很可能是你光源的 objectChange 写回路径里漏了某个字段或异步了一帧。

### **1.2 必须做的修复（三层保护，缺一不可）**

**保护 1：dragging 锁（这是核心）**

之前指导里已经有 dragging store。但要确认它**真的被 manager.update() 读取**。光源 manager 没读这个锁的概率很大，所以才独有问题。

**保护 2：objectChange 实时写回，不要等 dragging-changed=false**

```ts
// transform-controls-setup.ts
controls.addEventListener('objectChange', () => {
  const obj = controls.object;
  if (!obj) return;
  if (obj.userData?.role === 'group-helper') return;

  // 实时写回，每一帧都同步到 store
  // 这样即使失焦先于 dragging-changed=false 发生，store 也已经有最新值
  onObjectChange(obj);
});
```

如果担心性能（每帧都写 store），用 requestAnimationFrame 节流到 60fps：

```ts
let pendingRaf = 0;
controls.addEventListener('objectChange', () => {
  const obj = controls.object;
  if (!obj) return;
  if (obj.userData?.role === 'group-helper') return;
  if (pendingRaf) return;
  pendingRaf = requestAnimationFrame(() => {
    pendingRaf = 0;
    onObjectChange(obj);
  });
});
```

**保护 3：失焦的事件顺序保证**

最稳的做法是 **Three.js 画布上的失焦点击，必须等到当前帧的 dragging-changed 处理完之后再走 selectAny(undefined)**。实现方式是给画布的 click 失焦逻辑套一层 setTimeout(..., 0)：

```ts
canvas.addEventListener('pointerdown', (e) => {
  // 先让 TransformControls 自己处理 dragging-changed
  // 然后下一个微任务再判断是否要清空选中
  setTimeout(() => {
    if (raycaster 命中空白) {
      props.store.selectAny(undefined);
    }
  }, 0);
});
```

或者更优雅的方式：在 `dragging-changed=false` 处理完成后**立即同步触发一次 store.scene 更新**，让 update() 看到最新值再失焦：

```ts
controls.addEventListener('dragging-changed', (e: any) => {
  orbitControls.enabled = !e.value;
  if (e.value) {
    const obj = controls.object;
    if (obj?.userData?.id) props.store.startDrag(obj.userData.id, obj.userData.groupId);
  } else {
    // 拖拽结束，强制把当前 transform 写回 store
    const obj = controls.object;
    if (obj && obj.userData?.role !== 'group-helper') {
      onObjectChange(obj);  // 显式调用一次，确保 store 同步
    }
    props.store.endDrag();
  }
});
```

### **2.3 一个非常容易踩的坑**

很多人会在 `wrap()` 里这样写：

```ts
const members = [
  ...cylManager.findByGroupId(groupId),
  ...boxManager.findByGroupId(groupId),
  ...lightManager.findByGroupId(groupId),
];
```

但 `findByGroupId` 在 manager 里如果是这样写：

```ts
const findByGroupId = (gid: string) => entries().filter(e => e.groupId === gid);
```

而 manager.entries 的 entry 又是从 update() 里构造的：

```ts
entry = { id: o.id, obj, kind: o.kind /* ← 这里没存 groupId */ };
```

那么 `e.groupId` 永远是 undefined，`findByGroupId` 永远返回空数组。**update() 必须把 groupId 存进 entry**：

```ts
entry = { id: o.id, obj, kind: o.kind, groupId: o.groupId };
// 或者每次 update 都刷新
entry.groupId = o.groupId;
```

这是上一轮指导里写过但很容易遗漏的细节。

## 六、group-controller.ts 改造

```ts
export function createGroupController(
  scene: THREE.Scene,
  managers: { cyl: CylinderManager; box: BoxManager; light: LightManager }
) {
  const helpers = new Map<string, THREE.Group>();

  const collectMembers = (groupId: string) => [
    ...managers.cyl.findByGroupId(groupId),
    ...managers.box.findByGroupId(groupId),
    ...managers.light.findByGroupId(groupId),
  ];

  const wrap = (groupId: string): THREE.Group | null => {
    const members = collectMembers(groupId);
    console.log('[wrap]', { groupId, memberCount: members.length });
    if (members.length === 0) return null;

    let helper = helpers.get(groupId);
    if (!helper) {
      helper = new THREE.Group();
      helper.name = `group-helper-`;
      helper.userData.role = 'group-helper';
      helper.userData.groupId = groupId;
      scene.add(helper);
      helpers.set(groupId, helper);
    }

    const center = new THREE.Vector3();
    members.forEach(m => center.add(m.obj.position));
    center.divideScalar(members.length);

    helper.position.copy(center);
    helper.rotation.set(0, 0, 0);
    helper.scale.set(1, 1, 1);

    for (const m of members) {
      helper.attach(m.obj);   // 必须 attach，不能 add
    }

    return helper;
  };

  const unwrap = (groupId: string, store: Shot3DStore) => {
    const members = collectMembers(groupId);
    for (const m of members) {
      const originGroup = 
        m.kind === 'cylinder' ? managers.cyl.group :
        m.kind === 'box' ? managers.box.group :
        managers.light.group;
      originGroup.attach(m.obj);  // 还原父，保留世界变换
      
      const updateFn = 
        m.kind === 'cylinder' ? store.updateCylinder :
        m.kind === 'box' ? store.updateBox :
        store.updateLight;
      updateFn(m.id, {
        position: { x: m.obj.position.x, y: m.obj.position.y, z: m.obj.position.z },
        rotation: { x: m.obj.rotation.x, y: m.obj.rotation.y, z: m.obj.rotation.z },
        scale:    { x: m.obj.scale.x,    y: m.obj.scale.y,    z: m.obj.scale.z    },
      });
    }
    const helper = helpers.get(groupId);
    if (helper) {
      scene.remove(helper);
      helpers.delete(groupId);
    }
  };

  return { wrap, unwrap };
}
```

## 七、ThreeViewport.tsx Effect 2 改造

```tsx

    boxManager.entries(),
    lightManager.entries(),
```

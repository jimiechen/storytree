## **二、长期定位（半年到一年的目标）**

### **2.1 一句话定义**


```text

不是普通付费插件（不能被禁用 / 卸载）
```

```text
Shot               镜头（由 Storyboard 插件消费 / 写回）
```

### **2.4 它和下游插件的关系**


下游插件可以随便加、随便买、随便禁用，但 **小说编辑器不能动**。

## **六、明天开工最容易犯的三个范围错误（要警惕）**

第一个是 **"顺手做角色卡 UI"**。Character / Location 的 UI 不在 MVP 范围内，但因为数据结构里有，开发时会本能地想加 CRUD 界面。一旦上手就会拉走半天到一天。**请用"今天先不做"的纪律压住**。

第二个是 **"AI Skill 写得太像产品"**。Skill 在 MVP 阶段只需要保证 Mock Provider 能返回结构稳定的 JSON，写得太花哨反而拖慢节奏。两个 SKILL.md 各 1 小时内完成，不要打磨到完美。

第三个是 **"提前接入 Storyboard Plugin"**。Shot 数据虽然属于"分镜"领域，但 MVP 不能让它跨进 Plugin 概念。所有 shot 相关的逻辑都直接写在 `packages/novel-core` 或 `packages/app/src/novel`，**不要建 plugin 目录、不要写 manifest**。等 M3 再把 shot 相关代码迁出来变成 Storyboard Plugin。

## **七、需要你今晚最终拍板的两件事**

下面这两件事我一直没拿到你的明确确认，建议今晚定下来再睡：

第一件，**编辑器是否需要支持 Markdown 输入？** MVP 阶段我倾向"纯文本，不支持 Markdown"，因为一旦支持就要决定要不要渲染，复杂度上升。但如果你打算让用户从飞书 / Notion / 番茄小说复制内容进来，至少要能 **保留段落分隔**。建议折中方案：纯文本，但对 `\n\n` 做段落渲染，仅此而已。

第二件，**是单文件项目还是项目目录？** 单文件 `.novelproj.json` 简单，但未来加资产（图像 / 音频）时会撑爆。项目目录（一个文件夹包含 `project.json` + `assets/` + `chapters/`）更适合长期。MVP 我建议先单文件，**但在 schemaVersion 里预留一个 `assetsDir` 字段**，未来切换到目录模式不破坏老存档。如果你今晚就想一步到位，我们可以直接做项目目录方案，多花 2 小时但 M3 之后省掉一次迁移。

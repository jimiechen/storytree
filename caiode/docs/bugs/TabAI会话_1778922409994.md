### **根因明确：Three.js r169+ 的 `TransformControls.detach()` 本身**不会**把 mesh 从父节点移除；圆柱体消失的真凶是你自己写的 `groupCtx.attachGroup(...)` 在失焦分支把所有 mesh 重新 parent 到了 groupCtx.group，而这个 group 要么 `visible=false`、要么没加进 scene，导致 mesh 视觉上消失。换句话说，问题不在 `detach`，在“失焦后多写了一段不该写的 group 接管逻辑”。

## **一、先纠正一个关键误判**

报告里的核心假设是：

```text
TransformControls.detach() 会调用 object.removeFromParent()
```

这个假设 **是错的**。

Three.js 自 r150+ 起，`TransformControls.attach(object)` 只是把 `this.object = object` 并显示 gizmo，**完全不改 mesh 的 parent**。`detach()` 只是把 `this.object = null` 并隐藏 gizmo，**也不会调用 `removeFromParent`**。

所以你看到 mesh “消失”不是 detach 干的。如果 detach 真会移除 mesh，那 r169 之后所有 Three.js 用户都用不了 TransformControls 了——这不可能。

报告里方案 A 加的 `originalParent` 补救逻辑，其实是在解决一个 **不存在的问题**，反而引入了新的副作用：

```text
detach 前后 mesh.parent 始终是 cylManager.group
你写的 if (originalParent && !currentObject.parent) 永远不成立
所以 originalParent.add() 永远不会执行
但你已经在错误方向上花了 3 轮修复时间
```

## **二、真正的根因：Effect 2 的失焦分支调了 `groupCtx.attachGroup(meshes)`**

看这段代码：

```ts
} else {
  transformCtx.attach(null);
  if (s.cylinders.length > 0) {
    groupCtx.group.visible = true;
    const meshes = Array.from(cylManager.group.children) as THREE.Object3D[];
    groupCtx.attachGroup(meshes);     // ← 真正的元凶
  } else {
    groupCtx.detachGroup();
    groupCtx.group.visible = false;
  }
}
```

“attachGroup(meshes)” 这个 API 顾名思义是**把传入的 meshes 全部 add 到 groupCtx.group 里**（类似多选编组的 transform helper 实现）。一旦执行：

```text
原本 cylManager.group.children = [mesh-A, mesh-B]
执行 groupCtx.group.add(mesh-A); groupCtx.group.add(mesh-B);
Three.js 自动从旧 parent 移除：cylManager.group.children = []
现在 mesh 全部在 groupCtx.group 里
```

而 groupCtx.group：
- 大概率**没被 add 到 scene**，或者
- `visible` 被前面/后面某行代码又设回 false，或者
- 它的 `matrix` / `position` 把整个组挪走了

**任何一种都会让所有圆柱体瞬间消失。**

加上你的 effect 拆分逻辑：每次 selectCylinder(undefined) → Effect 1 跑 update → setEntries → Effect 2 跑失焦分支 → attachGroup → mesh 离开 cylManager.group → 下一帧 Effect 1 再跑（因为 cylinders 数组又是新引用）→ update 里 `meshMap.get(c.id)` 还能拿到旧 mesh 引用，于是 `mesh.position.set(...)` 也能跑，但 mesh 此刻已经在 groupCtx.group 里，不在被渲染的可见路径上。

这也解释了报告里说的“状态不同步”：UI 看起来还有数据（store 里 cylinders 没动），但场景里啥都没。

## **三、修复策略：删掉 groupCtx 那一段，回归极简 attach/detach**

整个失焦分支根本不需要 group helper，也不需要 originalParent，也不需要 requestAnimationFrame 延迟。

正确的失焦逻辑只有一句话：

```text
没有选中 → detach gizmo → 隐藏 helper → 结束
不要碰 mesh，不要改 parent，不要换 group。
```

### **修复 1：transform-controls-setup.ts 回归极简**

把方案 A 的 originalParent 全部删掉。

```ts
// transform-controls-setup.ts
import * as THREE from 'three';
import { TransformControls } from 'three/examples/jsm/controls/TransformControls.js';

export interface TransformContext {
  controls: TransformControls;
  helper: THREE.Object3D;
  attach: (mesh: THREE.Object3D | null) => void;
  setMode: (mode: 'translate' | 'rotate' | 'scale') => void;
  dispose: () => void;
}

export function setupTransformControls(
  camera: THREE.Camera,
  renderer: THREE.WebGLRenderer,
  scene: THREE.Scene,
  orbitControls: { enabled: boolean },
  onObjectChange: (obj: THREE.Object3D) => void,
): TransformContext {
  const controls = new TransformControls(camera, renderer.domElement);
  const helper = controls.getHelper();   // r169+ 必须用 getHelper()
  scene.add(helper);

  controls.setMode('translate');
  controls.setSize(1.0);

  controls.addEventListener('dragging-changed', (e: any) => {
    orbitControls.enabled = !e.value;
  });

  controls.addEventListener('objectChange', () => {
    const obj = controls.object;
    if (obj) onObjectChange(obj);
  });

  const attach = (mesh: THREE.Object3D | null) => {
    if (mesh) {
      // 幂等：已经 attach 同一个 mesh 就跳过
      if (controls.object !== mesh) {
        controls.attach(mesh);
      }
      helper.visible = true;
    } else {
      controls.detach();
      helper.visible = false;
    }
  };

  const setMode = (mode: 'translate' | 'rotate' | 'scale') => {
    controls.setMode(mode);
  };

  const dispose = () => {
    controls.detach();
    controls.dispose();
    helper.removeFromParent();
  };

  return { controls, helper, attach, setMode, dispose };
}
```

要点：

```text
1. detach 后只隐藏 helper，绝不动 mesh
2. 不保存 originalParent，不做 parent 恢复
3. attach 加幂等判断，避免重复 attach 同一个对象
4. helper 通过 getHelper() 拿到，scene.add(helper) 而不是 add(controls)
```

### **修复 2：ThreeViewport.tsx 彻底删掉 groupCtx 失焦分支**

### **修复 3：cylinder-manager.ts 的 position 重置要加保护**

报告里疑问点 3 是对的：每次 update 都无条件重置 position，会和 TransformControls 拖拽产生竞争。

修改：

```ts
const update = (cylinders: CylinderObject[], selectedId?: string): void => {
  const incomingIds = new Set(cylinders.map(c => c.id));

  for (const [id, mesh] of meshMap) {
    if (!incomingIds.has(id)) {
      group.remove(mesh);
      mesh.geometry.dispose();
      (mesh.material as THREE.Material).dispose();
      meshMap.delete(id);
    }
  }

  for (const c of cylinders) {
    let mesh = meshMap.get(c.id);
    const isNew = !mesh;

    if (!mesh) {
      mesh = createMesh(c);
      mesh.userData.id = c.id;
      mesh.userData.kind = 'cylinder';
      group.add(mesh);
      meshMap.set(c.id, mesh);
    }

    // 材质 / 高亮：始终更新
    const mat = mesh.material as THREE.MeshStandardMaterial;
    mat.color.set(c.color);
    const isSelected = c.id === selectedId;
    mat.emissive.set(isSelected ? '#ffaa00' : (c.glow ? c.color : '#000000'));
    mat.emissiveIntensity = isSelected ? 0.6 : (c.glow ? 0.4 : 0);

    // position：只在两种情况下回写
    //   (a) 新建 mesh
    //   (b) store 中的 position 与 mesh 当前 position 不一致（外部数据驱动）
    // 避免 TransformControls 拖拽过程中被 effect 中途覆盖
    const targetY = c.position.y + c.height / 2;
    const dx = Math.abs(mesh.position.x - c.position.x);
    const dy = Math.abs(mesh.position.y - targetY);
    const dz = Math.abs(mesh.position.z - c.position.z);
    if (isNew || dx > 1e-4 || dy > 1e-4 || dz > 1e-4) {
      mesh.position.set(c.position.x, targetY, c.position.z);
    }
  }

  const next: CylinderMeshEntry[] = [];
  for (const c of cylinders) {
    const m = meshMap.get(c.id);
    if (m) next.push({ id: c.id, mesh: m });
  }
  setEntries(next);
};
```

加这个 epsilon 比较的目的：拖拽时 store 还没同步，effect 也不会用旧 store 把 mesh 拉回去。

### **修复 4：objectChange 回写 store 加节流**

TransformControls 拖拽时 `objectChange` 每帧触发，如果直接调 `setScene`，会把 cylinders 数组每帧都换引用，Effect 1 跟着每帧跑 update，update 又可能回写 position……虽然修复 3 已经隔断了反向覆盖，但仍然浪费性能。

```ts
// setupTransformControls 里
let rafPending = false;
let lastObj: THREE.Object3D | null = null;

controls.addEventListener('objectChange', () => {
  lastObj = controls.object;
  if (rafPending) return;
  rafPending = true;
  requestAnimationFrame(() => {
    rafPending = false;
    if (lastObj) onObjectChange(lastObj);
  });
});
```

外面的 `onObjectChange` 回调里再调 `store.updateCylinder(id, {...})`。

```ts
const onObjectChange = (obj: THREE.Object3D) => {
  const id = obj.userData?.id;
  if (!id) return;
  store.updateCylinder(id, {
    position: {
      x: obj.position.x,
      // 注意：store 中存的是底面 y，mesh 中是中心 y
      y: obj.position.y - (obj.userData.height ?? 0) / 2,
      z: obj.position.z,
    },
  });
};
```

`obj.userData.height` 在 createMesh 时存一下：

```ts
mesh.userData.height = c.height;
```

## 一、MVP 原型目标

### 核心目标

本阶段目标**不是完成真实 AI 接入**，也不是完成完整小说创作平台，而是基于 **Mock 数据和 FakeAgentProvider**，验证 AI 小说编辑器的**最小产品闭环**。

### 最小业务链路

```
用户打开小说项目
    ↓
查看项目结构（章节、角色、世界观）
    ↓
选择章节并编辑正文
    ↓
查看角色卡与世界观信息（上下文参考）
    ↓
发起 AI 续写 / 改写 / 摘要任务
    ↓
FakeAgentProvider 返回模拟结果
    ↓
用户采纳或丢弃结果
    ↓
系统记录 AITask 与 AILog
```

### 范围限定

| ✅ 允许做 | ❌ 不允许做 |
|---------|-----------|
| Mock 数据模拟 | 接入真实 Agent |
| FakeAgentProvider | 调用真实模型 |
| Provider 抽象接口设计 | 访问真实远程 API |
| UI 页面原型展示 | 修改 opencode 上游核心源码 |
| 任务状态流转验证 | 引入真实 API Key |
| 编辑器写回逻辑 | 实现 Bash/WebFetch/WebSearch/Agent/Task 高权限工具 |

## 五、MVP 用户流程

### 流程 1：打开小说项目 📂

**触发条件**: 用户启动应用或从项目列表选择项目

**操作步骤**:
1. 用户进入工作台页面
2. 系统加载当前活跃的小说项目（Mock 数据）
3. 展示项目基本信息：名称、题材、简介、总字数、更新时间
4. 展示项目统计：章节数量、角色数量
5. 显示 Mock Mode Banner 提示

**通过标准**:
- [ ] 能看到至少 1 个 Mock 项目
- [ ] 能看到项目基本信息（名称、题材、字数等）
- [ ] 能看到 Mock 模式提示（Banner 或徽章）
- [ ] 不出现真实模型配置入口
- [ ] 不出现 API Key 输入框

---

### 流程 2：选择章节并编辑 ✏️

**触发条件**: 用户从章节列表点击某个章节

**操作步骤**:
1. 用户在左侧 ChapterList 中选择一个章节
2. 系统加载该章节的标题、正文、大纲、剧情要点
3. 中央编辑区展示 ChapterEditor
4. 右侧展示相关角色卡和世界观信息
5. 用户可以编辑正文内容

**通过标准**:
- [ ] 能看到至少 3 个 Mock 章节
- [ ] 能切换章节（点击不同章节切换显示）
- [ ] 能编辑当前章节正文（输入框或富文本编辑器）
- [ ] 能看到章节大纲和剧情目标（OutlinePanel）
- [ ] 章节状态正确显示（草稿/修订/完成）

---

### 流程 3：查看角色卡 👤

**触发条件**: 用户在编辑章节时查看右侧面板

**操作步骤**:
1. 系统自动加载与当前章节相关的角色列表
2. 右侧 CharacterPanel 展示角色卡片
3. 每张角色卡包含：姓名、身份、性格、目标、秘密、口吻
4. 展示角色之间的关系标签
5. 可选操作：设为上下文引用、固定角色卡、查看详细关系图

**通过标准**:
- [ ] 能看到至少 3 个 Mock 角色
- [ ] 能查看角色基本信息（姓名、身份、性格）
- [ ] 能查看角色口吻设定（speakingStyle）
- [ ] 能查看角色关系（relationships）
- [ ] 角色卡布局清晰，不影响主编辑区

---

### 流程 4：发起 AI Mock 任务 🤖

**触发条件**: 用户在 AITaskPanel 点击"执行"按钮

**支持的任务类型**:

| 任务类型 | 输入 | 预期输出 | Mock 行为 |
|---------|------|---------|----------|
| **续写 (Continue Writing)** | 当前章节正文末尾 N 字 | 续写段落（约 200-500 字） | 延迟 1-3 秒后返回固定文本 |
| **改写 (Rewrite)** | 选中的文本段落 | 改写后的段落 | 保持语义，调整表达方式 |
| **摘要 (Summarize)** | 完整章节正文 | 章节摘要（100-200 字） | 提取关键情节生成摘要 |
| **角色语气改写 (Voice Rewrite)** | 文本段落 + 目标角色 | 符合角色口吻的文本 | 模拟特定角色的语言风格 |

**操作步骤**:
1. 用户选择任务类型（续写/改写/摘要/语气改写）
2. 系统创建 AITask 实例，初始状态为 `pending`
3. 任务状态转为 `running`，UI 显示进度提示
4. FakeAgentProvider 处理请求（延迟 1-3 秒模拟网络耗时）
5. 任务状态转为 `success`，返回模拟结果
6. AIResultCard 展示结果，提供操作按钮

**通过标准**:
- [ ] 支持续写任务（能返回续写文本）
- [ ] 支持改写任务（能返回改写文本）
- [ ] 支持摘要任务（能返回摘要文本）
- [ ] 支持角色语气改写任务（能返回符合角色风格的文本）
- [ ] 任务状态流转正确：`pending` → `running` → `success`
- [ ] 不调用真实模型（无网络请求）
- [ ] 不调用真实 Agent（无工具执行）
- [ ] 不访问外部网络（纯本地 Mock）
- [ ] 任务执行有合理的延迟效果（1-3 秒）

---

### 流程 5：采纳或丢弃 AI 结果 ✓✗

**触发条件**: AI 任务成功返回结果后

**操作步骤**:
1. AIResultCard 以卡片形式展示模拟结果
2. 卡片显示：任务类型、状态徽章、生成的文本预览
3. 用户可选择以下操作之一：
   - **采纳到正文 (Accept)**: 将 AI 结果直接插入到编辑器光标位置或替换选中文本
   - **保存到建议区 (Save to Suggestions)**: 将结果保存到建议列表，供后续查看和使用
   - **丢弃 (Discard)**: 丢弃结果，不做任何保存
4. 操作完成后，AILog 记录本次操作（操作类型、时间戳）

**通过标准**:
- [ ] AI 结果以卡片形式展示（非弹窗、非模态框）
- [ ] 支持"采纳到正文"操作
- [ ] 支持"保存到建议区"操作
- [ ] 支持"丢弃结果"操作
- [ ] 操作后 AILog 有记录（包含操作类型和时间）
- [ ] 采纳后编辑器内容更新
- [ ] 丢弃后无残留数据

---

### 流程 6：查看 AI 日志 📋

**触发条件**: 用户点击 AILogDrawer 打开日志抽屉

**操作步骤**:
1. 用户点击全局日志按钮或图标
2. 右侧滑出 AILogDrawer 抽屉
3. 抽屉展示历史任务列表（按时间倒序）
4. 每条日志包含：任务 ID、任务类型、关联章节、输入摘要、输出摘要、状态、耗时、错误信息（如有）
5. 支持筛选：全部 / 成功 / 运行中 / 失败 / 已取消
6. 点击某条日志可展开查看详细信息（完整输入、完整输出、状态时间线）
7. 详情页明确标注："Generated by FakeAgentProvider - No real API call"

**通过标准**:
- [ ] 能看到任务列表（至少包含之前执行的 Mock 任务）
- [ ] 能看到多种状态：success / failed / cancelled / permission_denied / quota_exceeded
- [ ] 能看到 Mock 输出内容预览
- [ ] 能看到错误模拟记录（如有失败任务）
- [ ] 明确标识 Mock 模式（提示文字或徽章）
- [ ] 支持按状态筛选
- [ ] 支持查看单条任务的详细信息

## 六、必须覆盖的 Mock 状态

### 正常状态（5种）

| 状态 | 英文标识 | 展示方式 | 触发场景 | UI 表现 |
|-----|---------|---------|---------|--------|
| **等待中** | `pending` | Badge + 图标 | 任务已创建，等待执行 | 灰色/黄色 Badge，显示"等待中..." |
| **运行中** | `running` | Badge + 进度条/动画 | 任务正在处理中 | 蓝色 Badge + Spinner 动画，显示"处理中..." |
| **成功** | `success` | Badge + 结果卡片 | 任务正常完成 | 绿色 Badge + 对勾图标，显示"已完成" |
| **失败** | `failed` | Badge + 错误信息 | 任务执行出错 | 红色 Badge + 错误图标，显示错误原因 |
| **已取消** | `cancelled` | Badge + 提示 | 用户主动取消任务 | 灰色 Badge，显示"已取消" |

### 异常状态（2种）

| 状态 | 英文标识 | 展示方式 | 触发场景 | UI 表现 |
|-----|---------|---------|---------|--------|
| **权限拒绝** | `permission_denied` | Badge + 错误提示 | 模拟权限不足场景 | 橙红色 Badge，显示"权限不足"，提示联系管理员 |
| **配额不足** | `quota_exceeded` | Badge + 错误提示 | 模拟使用额度超限场景 | 橙色 Badge，显示"配额不足"，提示升级套餐 |

### 页面级状态（3种）

| 状态 | 展示方式 | 触发场景 | UI 表现 |
|-----|---------|---------|--------|
| **空状态 (Empty)** | 空状态插画 + 提示文字 | 项目列表为空、章节列表为空、角色列表为空 | 显示友好提示："暂无数据，点击创建第一个 XXX" |
| **加载中 (Loading)** | Skeleton 骨架屏 / Loading 动画 | 数据正在加载 | 显示占位骨架屏或居中 Loading 动画 |
| **Mock 模式标识** | 顶部 Banner 或角标 | 应用全局 | 固定显示 "🧪 Mock Mode - 模拟模式，不调用真实 AI" |

## 八、与 Mock 接入的关系

### 原型反推接口设计

产品原型不是额外工作，它应该**直接反推 Mock 接口的代码设计**：

#### 场景 1：AI 任务面板 → 后端接口需求

```
原型中有 AI 任务面板
    ↓
代码需要实现：
├── AITask                    (任务实体)
├── AITaskStatus              (任务状态枚举)
├── FakeAgentProvider.runTask()   (执行任务方法)
├── FakeAgentProvider.cancelTask() (取消任务方法)
├── AILog                     (日志实体)
└── AIResult                  (结果实体)
```

#### 场景 2：角色卡侧栏 → 后端接口需求

```
原型中有角色卡侧栏
    ↓
代码需要实现：
├── Character                 (角色实体)
├── CharacterVoice            (角色口吻设定)
├── CharacterRelationship     (角色关系)
└── NovelCharacterProvider    (角色数据 Provider)
```

#### 场景 3：章节编辑器 → 后端接口需求

```
原型中有章节编辑器
    ↓
代码需要实现：
├── Chapter                   (章节实体)
├── ChapterDraft              (章节草稿)
├── ChapterOutline            (章节大纲)
└── NovelChapterProvider      (章节数据 Provider)
```

### Week 1 推进顺序

```
① 先定 MVP 原型清单（本文档）
    ↓
② 再定 Mock 数据结构和状态定义
    ↓
③ 再定 Provider 接口契约
    ↓
④ 再做 FakeAgentProvider 实现
    ↓
⑤ 最后接入页面展示（基于 opencode 的 Workspace/Page/Panel）
```

这样可以避免"接口写了一堆，但页面用不上"的问题。

## 九、负面约束清单

### 原型中禁止出现的元素

| 类别 | 禁止元素 | 原因 |
|-----|---------|------|
| **模型配置** | 真实 AI 模型 Provider 设置（OpenAI/Claude/Gemini 等） | Week 1 不接真实模型 |
| **密钥管理** | API Key 输入框、密钥存储、加密设置 | 不涉及真实认证 |
| **计费系统** | 订阅页面、账单、用量统计、套餐升级 | 无商业化功能 |
| **命令执行** | Terminal 面板、Shell/Bash 工具、命令行输入 | 高权限风险 |
| **网络搜索** | Web Search 工具、浏览器集成、URL 抓取 | 外部访问风险 |
| **网页抓取** | Web Fetch 工具、爬虫功能、HTML 解析 | 外部访问风险 |
| **Agent 系统** | 多 Agent 编排、Agent 协作、Agent 市场 | 复杂度过高 |
| **部署运维** | 部署设置、Docker 配置、CI/CD 面板 | 运维范畴 |
| **插件系统** | 插件市场、插件安装、插件管理 | 需进一步确认边界 |
| **管理后台** | Admin Dashboard、用户管理、权限管理 | 非 MVP 范围 |
| **社交功能** | 社区、评论、分享、协作编辑 | 非核心功能 |
| **发布系统** | 平台发布、电子书导出、格式转换 | 后置功能 |
| **区块链/NFT** | 代币、NFT铸造、数字资产 | 完全无关 |

### 设计风格禁止项

| 禁止风格 | 原因 | 替代方案 |
|---------|------|---------|
| 游戏化 UI | 不是游戏平台 | 专业写作工具风格 |
| 赛博朋克风格 | 与产品调性不符 | 温暖创意写作氛围 |
| 终端/命令行风格 | 不面向开发者用户 | 友好的图形界面 |
| 聊天机器人优先布局 | 不是对话产品 | 编辑器优先布局 |
| 过度多彩仪表盘 | 干扰写作专注度 | 柔和中性色调 |
| 重渐变/玻璃态 | 降低可读性 | 扁平化、清晰层次 |

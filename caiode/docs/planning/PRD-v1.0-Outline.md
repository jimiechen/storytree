# 卡牌物语 · AI 小说编辑器 · 概要设计 PRD v1.0 大纲

> **版本**：v1.0  
> **状态**：MVP 概要设计  
> **产品定位**：卡牌物语国际版配套的内部创作者工具  
> **技术基线**：OpenCode 二次开发  
> **Agent 策略**：Claude Code Agent 主力执行，OpenCode Agent 补充  
> **交付目标**：8-10 周完成内部 MVP / Alpha  
> **目标用户**：内部内容团队 + 首批受邀创作者  
> **核心目标**：用最小工程量跑通 AI 辅助小说生产、分支剧情编辑、本地沙箱隔离与内容同步发布闭环

---

## **第一章 · 项目背景与目标**

### **1.1 项目背景**

说明卡牌物语当前已经从国内版转向国际版，主产品聚焦 Web-only PWA、英语市场、互动阅读、卡牌收集与付费圈子。AI 小说编辑器不是独立商业产品，而是为主产品提供内容生产能力的内部工具。

### **1.2 产品定位**

定义 AI 小说编辑器的核心定位：它是"内容生产端"，不是读者端，也不是面向全网开放的创作 SaaS。它服务于内部团队和受邀创作者，帮助快速生成、编辑、检查和发布互动小说内容。

### **1.3 MVP 目标**

MVP 只验证一个核心闭环：创作者创建项目 → 建立角色与世界观 → AI 生成章节 → 编辑分支剧情 → 一致性检查 → 同步到卡牌物语内容底座。

### **1.4 非目标范围**

明确 v1.0 不做通用协作编辑、不做公开注册、不做复杂素材生产、不做卡牌美术生成、不做完整商业化后台、不做移动端编辑器。

### **1.5 成功标准**

定义内部 MVP 的验收口径，例如 2-3 名内部成员连续使用两周、完成至少 10 章英文互动内容、生成 30 张异兽卡牌文案、跑通至少 20 个分支节点、成功同步到主产品测试环境。

---

## **第二章 · 用户角色与使用场景**

### **2.1 用户角色**

划分三类用户：内部内容生产者、受邀创作者、平台管理员。每类用户的权限、目标和使用频率不同。

### **2.2 内部内容生产场景**

内部团队用编辑器快速生产卡牌物语首批种子内容，包括英文章节、异兽设定、分支节点、问答选项和章节摘要。

### **2.3 受邀创作者场景**

受邀创作者使用编辑器创建自己的互动故事，绑定到平台中的圈子或内容专栏，完成草稿、修改、检查和提交。

### **2.4 平台管理员场景**

管理员负责账号邀请、权限分配、配额管理、日志审计、异常任务处理和内容发布状态检查。

### **2.5 核心用户旅程**

描述从首次登录、创建项目、配置故事设定、调用 AI 生成内容、修改章节、添加分支、同步发布的完整路径。

---

## **第三章 · MVP 范围定义**

### **3.1 MVP 必做能力**

MVP 必须包含项目管理、章节编辑、角色卡、世界观设定、AI 续写/改写/扩写、多分支剧情、本地沙箱、同步发布、调用日志和基础配额。

### **3.2 MVP 可降级能力**

分支可视化、工作流编排、全文一致性检查、批量章节生成、多 Agent 协作可以做简化版本，优先保证主链路跑通。

### **3.3 MVP 不做能力**

不做实时多人协作、不做公开创作者平台、不做复杂支付结算、不做完整内容审核系统、不做移动端 App、不做视频剧本、不做卡牌设计器。

### **3.4 功能优先级分层**

按照 P0、P1、P2 拆分功能。P0 是必须交付的写作与同步闭环；P1 是提升效率的 AI 工作流；P2 是后续增强能力。

---

## **第四章 · 总体架构设计**

### **4.1 架构原则**

采用 local-first、本地沙箱隔离、Agent 可替换、同步解耦、最小后端依赖的设计原则。

### **4.2 总体架构图**

展示编辑器前端、OpenCode 二开层、Claude Code Agent 适配层、OpenCode Agent 补充层、本地 SQLite、文件系统、模型网关、后端服务之间的关系。

### **4.3 客户端架构**

说明客户端由 UI 层、编辑器核心层、Agent 调度层、沙箱管理层、同步层、本地存储层组成。

### **4.4 后端依赖架构**

说明编辑器依赖 UserSvc、CircleSvc、NovelSvc、AssetSvc、QuotaSvc 等服务，但不把编辑器内部状态强绑定到后端。

### **4.5 数据流总览**

描述从用户输入写作指令，到 Agent 读取上下文、调用模型、写入章节、本地保存、同步发布的完整数据流。

## **第五章 · OpenCode 二次开发方案**

### **5.1 选择 OpenCode 的原因**

说明选择 OpenCode 二开的核心原因：已有 Agent 工具框架、会话管理、文件操作能力、项目目录结构、任务执行机制，比从零开发桌面编辑器更快。

### **5.2 保留能力**

保留 OpenCode 的项目结构、会话管理、工具调用、文件读写、任务状态、日志输出、插件扩展和部分 UI 组件。

### **5.3 改造能力**

重点改造为小说创作场景，包括项目面板、章节树、角色卡、世界观库、剧情分支树、写作指令面板和发布入口。

### **5.4 移除或隐藏能力**

隐藏与代码开发强相关但小说创作者不需要的界面元素，降低工具感和认知负担。

### **5.5 插件化扩展点**

设计小说插件、分支剧情插件、同步发布插件、内容检查插件、模型路由插件等扩展点。

### **5.6 Fork 维护策略**

锁定当前稳定版本，MVP 阶段不追上游新特性，只做最小可控改造。后续按季度评估是否合并上游更新。

## **第六章 · Agent 架构设计**

### **6.1 Agent 分工原则**

Claude Code Agent 作为主力执行 Agent，负责复杂任务执行、长上下文处理、文件级修改、章节生成和一致性检查。OpenCode Agent 作为补充，负责轻量任务、快速问答、辅助改写和 UI 内嵌提示。

### **6.2 主力 Agent 能力范围**

主力 Agent 负责大纲生成、章节扩写、章节改写、角色一致性检查、世界观冲突检查、分支剧情生成和批量任务执行。

### **6.3 补充 Agent 能力范围**

补充 Agent 负责局部润色、标题建议、摘要生成、标签生成、选项文案优化和轻量 prompt 交互。

### **6.4 Agent 调度策略**

根据任务类型、上下文长度、执行风险和成本选择不同 Agent。高复杂度任务交给主力 Agent，低复杂度任务交给补充 Agent。

### **6.5 Agent 工具白名单**

MVP 只开放安全工具，例如读取项目文件、写入章节文件、编辑指定文件、搜索项目内文本、读取角色卡、读取世界观设定、写入 AI 日志。

### **6.6 Agent 工具黑名单**

默认禁止执行系统命令、访问项目外文件、任意网络请求、读取环境变量、批量删除文件等高风险操作。

### **6.7 Agent 日志与可追溯性**

所有 AI 调用、工具调用、文件修改、失败重试和同步行为都要写入本地日志，关键事件同步到后台审计。

## **第七章 · 多沙箱设计**

### **7.1 沙箱定义**

沙箱是一个独立的工作目录、上下文环境和版本空间，用于隔离不同创作方案。

### **7.2 沙箱与项目关系**

一个项目可以包含多个沙箱。每个沙箱可以代表主线版本、实验版本、暗线版本、重写版本或不同风格版本。

### **7.3 Git Worktree 集成**

使用 worktree 思路管理多个沙箱，让不同版本的内容互不污染，并支持回滚、对比和摘取。

### **7.4 沙箱生命周期**

包括创建沙箱、复制沙箱、切换沙箱、重命名沙箱、归档沙箱、删除沙箱和从沙箱发布内容。

### **7.5 沙箱隔离边界**

Agent 只能访问当前沙箱目录，不能跨沙箱读取或写入。跨沙箱内容借用必须通过明确的用户操作触发。

### **7.6 MVP 降级方案**

如果 worktree 集成在第一周 PoC 中失败，则降级为普通目录复制方案，先保证多版本隔离能力。

---

## **第八章 · 多分支剧情设计**

### **8.1 分支剧情定义**

分支剧情是读者在阅读中基于选择、问答或条件进入不同叙事路径的结构。

### **8.2 分支与沙箱的关系**

沙箱是创作环境隔离，分支是故事结构。一个沙箱内可以包含多个剧情分支，二者不是同一个概念。

### **8.3 分支 DAG 模型**

分支剧情采用有向无环图结构。节点代表章节或剧情片段，边代表用户选择、问答结果或条件判断。

### **8.4 分支节点类型**

包括普通章节节点、选择节点、问答节点、隐藏节点、汇合节点和结局节点。

### **8.5 分支编辑能力**

创作者可以新增节点、连接节点、设置选项、设置进入条件、编辑节点内容、删除无效分支、合并分支路径。

### **8.6 分支可视化能力**

MVP 提供基础树状视图或列表视图，v1.1 再增强为完整画布式 DAG 编辑器。

### **8.7 与主产品问答分支的映射**

编辑器内的分支节点需要能同步到主产品已有的问答分支模型，保证读者端可以直接消费。

## **第九章 · 小说创作核心功能**

### **9.1 项目管理**

支持创建项目、绑定圈子、设置语言、设置题材、设置目标读者、配置默认 AI 风格。

### **9.2 章节管理**

支持章节列表、章节状态、章节排序、章节草稿、章节版本、章节摘要和章节发布状态。

### **9.3 富文本或 Markdown 编辑**

MVP 优先使用 Markdown 或轻量富文本，保证 AI 读写简单、文件结构清晰、版本管理方便。

### **9.4 角色卡管理**

支持角色名称、身份、性格、目标、关系、口癖、禁忌设定和出场章节。

### **9.5 世界观设定库**

支持地点、势力、物品、规则、时间线、异兽设定和文化背景设定。

### **9.6 AI 续写**

基于当前章节、角色卡和世界观继续生成后续内容。

### **9.7 AI 改写**

支持按风格、节奏、语气、长度、读者年龄段进行改写。

### **9.8 AI 扩写**

将大纲、剧情点或短段落扩写为完整章节。

### **9.9 AI 摘要与标签**

自动生成章节摘要、角色出场列表、剧情标签、分支标签和发布简介。

### **9.10 一致性检查**

检查角色设定冲突、时间线冲突、世界观冲突、前后文矛盾和分支断裂。

---

## **第十章 · AI 工作流引擎**

### **10.1 工作流定位**

工作流用于把多个 AI 操作串成稳定流程，例如"大纲 → 扩写 → 检查 → 修订 → 摘要 → 待发布"。

### **10.2 MVP 内置工作流**

MVP 内置 5 个基础工作流：大纲生成、章节扩写、章节润色、一致性检查、分支剧情生成。

### **10.3 工作流执行模式**

支持手动执行、单章节执行、批量章节执行和中断恢复。

### **10.4 工作流状态管理**

每个任务需要记录等待中、执行中、成功、失败、已取消和需人工确认等状态。

### **10.5 失败重试机制**

模型失败、超时、返回格式错误、工具调用失败时，需要有明确的重试和降级策略。

### **10.6 MVP 降级方案**

如果完整工作流引擎超出工期，则先做固定模板按钮，不开放自定义 DSL。

---

## **第十一章 · 本地数据与文件模型**

### **11.1 本地存储原则**

采用 local-first，所有创作内容优先保存在本地，发布时再同步到服务端。

### **11.2 文件目录结构**

定义项目目录、沙箱目录、章节目录、角色卡文件、世界观文件、分支文件、日志文件和配置文件。

### **11.3 SQLite 数据表**

设计 projects、sandboxes、chapters、characters、world_settings、branch_nodes、branch_edges、ai_tasks、ai_logs、sync_records 等表。

### **11.4 Markdown / JSON 文件规范**

章节正文使用 Markdown，结构化数据使用 JSON 或 SQLite，保证 Agent 易读易写。

### **11.5 版本记录**

每次 AI 修改和人工修改都应产生版本记录，支持对比、回滚和恢复。

### **11.6 备份与恢复**

支持本地备份、导出项目包、从备份恢复项目。

---

## **第十二章 · 后端同步设计**

### **12.1 同步目标**

编辑器只同步"准备发布"的内容，不同步全部草稿和全部沙箱状态。

### **12.2 登录认证**

复用已有用户体系，创作者登录后获取访问权限和可绑定圈子列表。

### **12.3 圈子绑定**

一个项目可以绑定到一个圈子或内容空间，用于后续发布章节和分支内容。

### **12.4 章节同步**

将本地章节同步为服务端章节草稿、待发布内容或正式发布内容。

### **12.5 分支同步**

将分支节点、选项、条件和剧情片段同步到主产品分支模型。

### **12.6 资产同步**

用于上传封面、卡牌图、异兽图、音频或其他素材。MVP 可只支持图片上传。

### **12.7 配额同步**

编辑器需要查询创作者剩余 AI 配额、任务次数和同步权限。

### **12.8 冲突处理**

若服务端内容和本地内容同时变化，MVP 优先采用人工确认覆盖策略，不做复杂自动合并。

---

## **第十三章 · 模型网关与成本控制**

### **13.1 模型网关定位**

编辑器不直接暴露模型 Key，所有 AI 请求通过统一模型网关转发、计量、限流和记录。

### **13.2 模型路由原则**

根据任务类型、上下文长度、成本、速度和失败率选择不同模型通道。

### **13.3 成本控制策略**

通过输入裁剪、上下文摘要、缓存、任务分级、配额上限、失败熔断控制成本。

### **13.4 配额模型**

按创作者、项目、任务类型设置月度 token 上限和调用次数上限。

### **13.5 失败回退**

当默认通道失败时，按预设顺序回退到备用通道；高成本通道只在必要任务中启用。

### **13.6 调用审计**

记录请求时间、任务类型、输入规模、输出规模、成本估算、失败原因和最终结果。

---

## **第十四章 · 权限、安全与内容治理**

### **14.1 账号权限**

只支持邀请制账号。普通创作者、内部编辑、管理员拥有不同权限。

### **14.2 本地文件安全**

限制 Agent 的文件访问范围，避免读取系统目录、其他项目目录或敏感配置文件。

### **14.3 Key 安全**

所有模型 Key 存放在服务端或模型网关，客户端不保存高权限 Key。

### **14.4 操作审计**

关键操作包括登录、创建项目、调用 AI、修改章节、删除沙箱、同步发布和配额异常。

### **14.5 内容分级策略**

编辑器 MVP 不做复杂内容审核，但需要保留内容分级标记、发布前确认、日志留存和管理员追溯能力。

### **14.6 滥用防护**

通过速率限制、配额限制、异常调用检测和账号冻结保护系统。

## **第十五章 · UI 与交互设计大纲**

### **15.1 主界面布局**

采用左侧项目与章节树，中间编辑区，右侧 AI 面板和设定面板，下方日志与任务状态栏的结构。

### **15.2 项目首页**

展示项目状态、绑定圈子、最近章节、AI 配额、待处理任务和同步状态。

### **15.3 章节编辑页**

提供正文编辑、AI 指令、版本记录、摘要、发布状态和关联分支入口。

### **15.4 角色卡页面**

支持角色列表、角色详情、关系备注和 Agent 上下文引用。

### **15.5 世界观页面**

支持设定分类、检索、引用和冲突检查。

### **15.6 分支剧情页面**

MVP 采用基础树状视图或表格视图，支持创建节点、连接节点、编辑选项和预览路径。

### **15.7 AI 任务面板**

展示当前任务、历史任务、失败任务、重试按钮和输出结果。

### **15.8 同步发布面板**

展示待发布章节、分支节点、资产列表、校验结果和发布按钮。

## **第十六章 · API 与协议设计大纲**

### **16.1 编辑器到后端 API**

包括登录、获取圈子、同步章节、同步分支、上传资产、查询配额、提交发布、查询发布状态。

### **16.2 编辑器到模型网关 API**

包括普通生成、结构化生成、长文本检查、批量任务、流式响应和调用记录。

### **16.3 编辑器内部 Agent RPC**

定义 UI 层与 Agent 层之间的任务提交、任务取消、任务状态查询、工具调用结果返回等协议。

### **16.4 数据结构规范**

定义 Project、Sandbox、Chapter、Character、WorldSetting、BranchNode、BranchEdge、AITask、SyncRecord 等核心对象。

### **16.5 错误码规范**

覆盖认证失败、权限不足、配额不足、模型失败、同步冲突、文件访问失败、任务超时等错误类型。

## **第十七章 · MVP 里程碑与工时规划**

### **17.1 第 0 周：技术 PoC**

验证 OpenCode 本地构建、自定义工具、主力 Agent 调用、worktree 或目录沙箱、模型网关连通性。

### **17.2 第 1-2 周：编辑器基础壳**

完成项目管理、章节管理、本地文件结构、本地数据库和基础 UI 改造。

## **第十八章 · 验收标准**

### **18.1 功能验收**

验证项目创建、章节生成、章节编辑、角色卡、世界观、分支节点、AI 检查、沙箱隔离、同步发布是否全部跑通。

### **18.2 性能验收**

验证启动速度、章节打开速度、AI 首 token 响应、章节保存速度、同步耗时和大项目加载表现。

### **18.3 稳定性验收**

连续使用两周，无严重数据丢失，无无法恢复的任务失败，无 Agent 越权访问。

### **18.4 内容生产验收**

内部团队使用编辑器完成卡牌物语 MVP 所需的首批内容：至少 10 章英文互动内容、30 张异兽卡牌文案、20 个问答/选择分支节点。

### **18.5 同步验收**

编辑器生成内容能够成功进入主产品测试环境，并被读者端正确渲染。

## **第十九章 · 风险与降级方案**

### **19.1 OpenCode 二开风险**

如果代码结构复杂、构建困难或改造成本超预期，则优先保留核心能力，减少 UI 重塑。

### **19.2 主力 Agent 集成风险**

如果主力 Agent 集成不稳定，则先使用命令行子进程方式接入，UI 层只做任务提交和结果展示。

### **19.3 多沙箱风险**

如果 worktree 方案延期，则降级为目录复制方案。

### **19.4 分支可视化风险**

如果画布式分支编辑成本过高，则降级为树状列表和表格编辑。

### **19.5 工作流引擎风险**

如果自定义工作流超期，则降级为固定模板按钮。

### **19.6 同步冲突风险**

如果自动合并复杂度过高，则采用人工确认覆盖策略。

### **19.7 AI 成本风险**

如果调用成本超过预算，则降低默认上下文、限制批量任务、启用摘要缓存和月度配额。

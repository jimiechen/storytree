# 卡牌物语 · AI 小说编辑器 · 概要设计 PRD v1.0

> **版本**：v1.0  
> **状态**：MVP 概要设计  
> **产品定位**：卡牌物语国际版配套的内部创作者工具  
> **技术基线**：OpenCode 二次开发  
> **Agent 策略**：Claude Code Agent 主力执行，OpenCode Agent 补充  
> **交付目标**：8-10 周完成内部 MVP / Alpha  
> **目标用户**：内部内容团队 + 首批受邀创作者  
> **核心目标**：用最小工程量跑通 AI 辅助小说生产、分支剧情编辑、本地沙箱隔离与内容同步发布闭环

## **第一章 · 项目背景与目标**

### **1.1 项目背景**

卡牌物语当前已经从国内版转向国际版，主产品聚焦 Web-only PWA、英语市场、互动阅读、卡牌收集与付费圈子。AI 小说编辑器不是独立商业产品，而是为主产品提供内容生产能力的内部工具。

在主产品快速迭代的背景下，内容生产能力成为制约业务增长的关键瓶颈。传统的纯人工创作方式在面对大量卡牌故事、互动分支、异兽设定等内容的生产需求时，效率低下且质量一致性难以保证。因此，我们需要构建一个专为互动小说创作场景设计的 AI 辅助工具，帮助内容团队快速生成高质量的互动小说内容。

当前市场上虽然存在各类 AI 写作工具和小说编辑器，但缺乏专门针对互动阅读场景（分支剧情、多角色、多世界设定）设计的解决方案。OpenCode 作为开源的 AI 编程工具，其架构设计（会话管理、工具调用、项目结构、Agent 调度）与我们需要的创作工具高度契合，通过二次开发可以快速构建所需的创作环境。

### **1.2 产品定位**

定义 AI 小说编辑器的核心定位：它是"内容生产端"，不是读者端，也不是面向全网开放的创作 SaaS。它服务于内部团队和受邀创作者，帮助快速生成、编辑、检查和发布互动小说内容。

具体而言，编辑器的产品定位包含以下几个维度：

第一，它是专业创作工具而非通用 AI 助手。编辑器深度集成故事创作的领域知识，包括角色一致性管理、世界观冲突检测、分支剧情建模等通用 AI 工具不具备的能力。

第二，它是本地优先的创作环境而非纯云端服务。创作者可以在本地拥有完整的创作控制权，所有内容优先保存在本地，只有在明确发布意图时才同步到服务端，降低网络依赖和数据风险。

第三，它是封闭生态的内部工具而非开放平台。账号采用邀请制，不开放公开注册，确保内容质量和平台安全性。

### **1.3 MVP 目标**

MVP 只验证一个核心闭环：创作者创建项目 → 建立角色与世界观 → AI 生成章节 → 编辑分支剧情 → 一致性检查 → 同步到卡牌物语内容底座。

这个闭环的每个环节都必须能够正常工作，任何一个环节的缺失都意味着 MVP 无法达成。具体而言，MVP 需要验证以下关键假设：

创作者能否顺利完成项目创建和初始化配置；角色卡和世界观设定能否被正确创建和引用；AI 能否基于上下文生成符合质量要求的章节内容；分支剧情能否被可视化和编辑；AI 检查能否发现常见的一致性问题；本地内容能否成功同步到主产品底座。

### **1.4 非目标范围**

明确 v1.0 不做通用协作编辑、不做公开注册、不做复杂素材生产、不做卡牌美术生成、不做完整商业化后台、不做移动端编辑器。

这些非目标并非不重要，而是需要在 MVP 验证核心假设后再逐步纳入后续版本规划。通用协作编辑需要解决冲突处理和权限细化问题，这些在 MVP 阶段会增加不必要的复杂度。公开注册需要完整的内容审核和用户管理系统，属于平台化阶段的特性。卡牌美术生成需要与美术团队协作定义风格规范，属于独立的能力模块。移动端编辑器需要单独的产品设计和技术方案，且创作场景本身更适合桌面环境。

### **1.5 成功标准**

定义内部 MVP 的验收口径，例如 2-3 名内部成员连续使用两周，完成至少 10 章英文互动内容、生成 30 张异兽卡牌文案、跑通至少 20 个分支节点、成功同步到主产品测试环境。

成功标准的设计遵循以下原则：可量化、可验证、有意义。可量化意味着有明确的数字指标；可验证意味着可以客观检查达成情况；有意义意味着这些指标真正反映了产品价值。

具体验收指标包括功能完整性（所有 MVP 功能点都能正常使用）、性能达标（启动时间、响应速度在可接受范围）、稳定性可靠（连续使用无数据丢失、无崩溃）、内容产出（能够实际生产出满足主产品需求的互动内容）、同步验证（内容能够成功进入主产品并被正确渲染）。

## **第二章 · 用户角色与使用场景**

### **2.1 用户角色**

划分三类用户：内部内容生产者、受邀创作者、平台管理员。每类用户的权限、目标和使用频率不同。

内部内容生产者是卡牌物语公司的全职内容团队成员，他们具备较高的技术素养和内容创作经验，使用编辑器的频率最高，目标是快速、高质量地生产大量互动小说内容。他们需要完整的项目管理和批量处理能力。

受邀创作者是外部合作的专业小说作者或内容创作者，他们具备优秀的创作能力但可能对技术工具不太熟悉，使用编辑器的频率适中，目标是创作出优秀的互动故事作品并获取收益。他们需要清晰的引导和简化的操作流程。

平台管理员是负责运营和管理创作平台的内部分员，他们关注账号管理、权限配置、配额分配、日志审计和异常处理，不直接参与内容创作但需要确保平台健康运行。

### **2.2 内部内容生产场景**

内部团队用编辑器快速生产卡牌物语首批种子内容，包括英文章节、异兽设定、分支节点、问答选项和章节摘要。

典型的工作流程是：内容策划完成故事大纲后，导入到编辑器中；创建项目中包含的所有角色卡和世界观设定；调用 AI 批量生成章节初稿；创作者逐章审核和修改；添加分支节点和读者选项；运行一致性检查确保角色和世界观的一致性；最后将审核通过的章节同步到主产品底座。

这个场景的核心需求是高效率（批量生成、快速迭代）、高质量（一致性检查、多轮修订）和可追溯（版本历史、修改记录）。

### **2.3 受邀创作者场景**

受邀创作者使用编辑器创建自己的互动故事，绑定到平台中的圈子或内容专栏，完成草稿、修改、检查和提交。

与内部团队不同，受邀创作者通常从零开始创作，更加依赖 AI 的辅助能力。他们可能对互动小说的结构不太熟悉，需要通过 AI 生成示例来学习参考；他们可能对分支剧情的复杂性感到困扰，需要可视化工具来理解和编辑。

典型的工作流程是：创作者注册并登录编辑器；创建新项目并设置基本参数；在 AI 辅助下逐步构建角色、世界观和章节；使用 AI 生成和优化分支选项；与编辑或策划讨论并修改；提交审核并等待反馈；根据反馈修改后重新提交。

### **2.4 平台管理员场景**

管理员负责账号邀请、权限分配、配额管理、日志审计、异常任务处理和内容发布状态检查。

账号邀请流程是：管理员在后台创建邀请链接或直接发送邀请邮件；受邀创作者通过链接完成注册；管理员设置创作者的权限级别和初始配额。

配额管理涉及：为不同级别的创作者设置不同的 AI 调用配额；监控配额使用情况并及时调整；处理配额不足的异常情况。

日志审计包括：追踪所有关键操作（登录、创建项目、AI 调用、内容修改、发布）；定期审查异常行为；生成运营报表支持决策。

### **2.5 核心用户旅程**

描述从首次登录、创建项目、配置故事设定、调用 AI 生成内容、修改章节、添加分支、同步发布的完整路径。

用户旅程的第一阶段是 onboarding。用户首次登录编辑器后，系统引导用户完成初始配置，包括设置创作偏好、选择 AI 模型风格、了解基本操作。系统展示示例项目帮助用户理解编辑器的使用方式。

第二阶段是项目初始化。用户创建新项目并设置基本信息，包括项目名称、绑定的圈子、目标语言、题材类型、目标读者群体。然后导入或创建角色卡和世界观设定，建立故事的设定基础。

第三阶段是内容创作。这是旅程的核心阶段，用户可以单章节或批量生成内容。AI 基于当前章节上下文、角色设定、世界观约束生成续写内容。用户修改和优化 AI 生成的内容，确保符合创作意图。AI 提供改写和润色建议，用户选择接受或拒绝。循环迭代直到内容达到发布标准。

第四阶段是分支构建。用户为章节添加分支节点，创建读者选择、问答选项或条件触发。系统可视化展示分支结构，用户可以清晰看到不同的剧情路径。

第五阶段是质量检查。用户运行一致性检查，系统扫描可能存在的角色设定冲突、时间线矛盾、世界观错误。检查报告列出所有问题，用户逐一处理。

第六阶段是发布同步。用户选择待发布的内容，编辑器与主产品底座同步。系统显示同步进度和结果。发布后用户可以在主产品中预览实际效果。

## **第三章 · MVP 范围定义**

### **3.1 MVP 必做能力**

MVP 必须包含项目管理、章节编辑、角色卡、世界观设定、AI 续写/改写/扩写、多分支剧情、本地沙箱、同步发布、调用日志和基础配额。

项目管理能力包括创建项目、删除项目、导入导出项目、查看项目列表和项目详情。这些是所有创作活动的基础。

章节编辑能力包括创建章节、编辑章节内容、删除章节、章节排序、章节状态管理和章节版本历史。章节是故事内容的基本单元。

角色卡能力包括创建角色、编辑角色设定、删除角色、角色列表和角色关系管理。角色是故事的核心要素。

世界观设定能力包括创建世界观条目（地点、势力、物品、规则等）、编辑条目内容、删除条目和条目分类管理。世界观为故事提供宏观背景。

AI 续写/改写/扩写能力是核心价值所在。续写基于当前内容继续生成；改写按照指定风格或要求重新组织内容；扩写将简略内容扩展为完整章节。

多分支剧情能力包括创建分支节点、连接节点构成分支树、编辑分支选项和条件、删除和合并分支路径。分支是互动阅读的核心特性。

本地沙箱能力包括创建多个沙箱版本、切换沙箱、隔离不同创作方案、避免版本污染。沙箱支持创意探索而不影响主线进度。

同步发布能力包括登录认证、绑定圈子、同步章节和分支到主产品、上传资产和查看发布状态。这是编辑器的输出闭环。

调用日志能力包括记录所有 AI 调用、查看历史调用、失败重试和异常告警。日志是问题排查和优化改进的基础。

基础配额能力包括显示当前配额余额、配额使用统计和配额不足提醒。合理的配额管理控制成本。

### **3.2 MVP 可降级能力**

分支可视化、工作流编排、全文一致性检查、批量章节生成、多 Agent 协作可以做简化版本，优先保证主链路跑通。

分支可视化 MVP 可以用树状列表或简单表格替代完整的画布式编辑器。工作流编排 MVP 可以用固定模板按钮替代可配置的 DSL。全文一致性检查 MVP 可以只做局部检查而非全量扫描。批量章节生成 MVP 可以做但功能简化。多 Agent 协作 MVP 可以只实现主力 Agent。

### **3.3 MVP 不做能力**

不做实时多人协作、不做公开创作者平台、不做复杂支付结算、不做完整内容审核系统、不做移动端 App、不做视频剧本、不做卡牌设计器。

这些能力在 MVP 验证产品价值后会逐步纳入后续版本规划。

### **3.4 功能优先级分层**

P0 是必须交付的写作与同步闭环；P1 是提升效率的 AI 工作流；P2 是后续增强能力。

P0 功能包括项目管理、章节编辑、角色卡、世界观设定、AI 续写改写扩写、多分支剧情（基础版）、本地沙箱（基础版）、同步发布（基础版）、调用日志。

P1 功能包括分支可视化（树状视图）、基础工作流（固定模板）、局部一致性检查、批量章节生成（简化版）。

P2 功能包括画布式分支编辑器、可配置工作流 DSL、全文一致性检查报告、完整多 Agent 协作、移动端编辑器。

## **第四章 · 总体架构设计**

### **4.1 架构原则**

local-first 是核心原则。所有创作内容优先保存在本地，只有明确的发布操作才会触发与服务端的同步。这种设计确保创作者始终拥有对内容的完整控制，降低网络依赖，即使离线也能正常工作。

本地沙箱隔离确保不同创作方案（主线、实验线、暗线）互不干扰。沙箱边界清晰，Agent 只能在当前沙箱内操作，无法访问其他沙箱内容。

Agent 可替换意味着主力 Agent 和补充 Agent 都通过标准化接口接入。当更好的模型或 Agent 方案出现时，可以平滑切换而不影响整体系统。

同步解耦确保编辑器的本地状态与后端状态独立管理。即使服务端暂时不可用，本地创作也不会中断；服务端恢复后通过明确的操作触发同步。

最小后端依赖减少系统复杂度和运维成本。MVP 阶段尽可能利用本地能力，后端只负责认证、权限和内容同步等必要功能。

### **4.2 总体架构图**

编辑器前端负责 UI 交互和内容展示，是用户操作的主要界面。

OpenCode 二开层是编辑器的技术底座，提供会话管理、工具调用、文件操作、项目结构等基础能力。

Claude Code Agent 适配层负责将 Claude Code Agent 的能力接入编辑器，处理复杂任务、长上下文和文件级修改。

OpenCode Agent 补充层负责处理轻量任务，包括局部润色、快速问答和辅助改写。

本地 SQLite 存储项目的结构化数据，包括项目配置、角色信息、分支结构、任务记录等。

文件系统存储章节内容、角色卡文档、世界观设定等文本内容，采用 Markdown 和 JSON 格式。

模型网关是所有 AI 调用的统一入口，负责路由、计量、限流和日志记录。

后端服务包括 UserSvc（用户认证）、CircleSvc（圈子管理）、NovelSvc（内容同步）、AssetSvc（素材管理）和 QuotaSvc（配额管理）。

### **4.3 客户端架构**

UI 层采用 OpenCode 的 TUI 或桌面应用 UI 进行定制化改造，适配小说创作场景的交互需求。

编辑器核心层处理章节编辑、角色管理、世界观管理、分支管理等核心业务逻辑。

Agent 调度层负责根据任务类型和复杂度选择合适的 Agent，处理 Agent 之间的协作和状态同步。

沙箱管理层管理多个沙箱的创建、切换、隔离和清理，确保创作环境的独立性和安全性。

同步层负责与后端服务通信，处理内容发布、素材上传和状态同步。

本地存储层管理 SQLite 数据库和文件系统，提供统一的数据访问接口。

### **4.4 后端依赖架构**

编辑器依赖 UserSvc 获取用户身份和权限信息，但不存储用户认证凭证。

编辑器依赖 CircleSvc 查询可绑定的圈子列表，获取圈子配置信息。

编辑器依赖 NovelSvc 将章节和分支内容同步到主产品底座，获取同步状态。

编辑器依赖 AssetSvc 上传封面、插图等素材，获取素材访问地址。

编辑器依赖 QuotaSvc 查询当前配额余额和使用情况，获取任务执行许可。

编辑器不将编辑器的内部状态（如草稿进度、AI 调用记录）与后端强同步，这些信息保留在本地。

### **4.5 数据流总览**

用户输入写作指令（如"续写本章"）触发数据流。

Agent 调度层接收指令，解析任务类型和上下文需求。

如果是复杂任务，选择 Claude Code Agent 作为执行者；如果是简单任务，选择 OpenCode Agent。

Agent 读取当前章节内容、相关角色卡、世界观设定，构建生成上下文。

Agent 调用模型网关发起 AI 请求，附带必要的系统提示和示例。

模型网关路由请求到合适的模型通道，执行生成并返回结果。

Agent 接收生成结果，进行必要的格式校验和后处理。

Agent 将生成内容写入本地文件，更新 SQLite 中的章节状态。

本地存储层持久化所有变更，生成版本记录。

用户确认发布后，同步层将发布内容推送到后端服务。

后端服务处理同步请求，更新主产品底座，返回同步结果。

同步层更新本地同步状态，记录同步日志。

## **第五章 · OpenCode 二次开发方案**

### **5.1 选择 OpenCode 的原因**

选择 OpenCode 二开的核心原因：已有 Agent 工具框架、会话管理、文件操作能力、项目目录结构、任务执行机制，比从零开发桌面编辑器更快。

OpenCode 的架构设计与我们的需求高度匹配。它采用 Monorepo 结构，便于模块管理和依赖共享。它使用 TypeScript 开发，类型安全且易于定制。它内置了会话管理、工具注册、任务调度等机制，可以直接复用。它拥有成熟的插件系统，支持功能扩展。它使用 Bun 作为运行时，性能优秀。

从零开发类似的桌面应用需要 3-4 个月，而基于 OpenCode 二次开发预计可以在 8-10 周内完成 MVP，节省 50% 以上的时间。

### **5.2 保留能力**

保留 OpenCode 的项目结构、会话管理、工具调用、文件读写、任务状态、日志输出、插件扩展和部分 UI 组件。

项目结构可以复用于组织小说项目，每个项目包含章节、角色卡、世界观等子目录。

会话管理可以复用于管理创作会话，支持会话历史和恢复。

工具调用框架可以复用于注册和执行 AI 工具，如续写、改写、扩写等。

文件读写能力可以复用于读取和写入 Markdown 章节文件。

任务状态管理可以复用于跟踪 AI 生成任务的状态和进度。

日志输出可以复用于记录 AI 调用和工具执行日志。

插件扩展机制可以复用于开发小说创作专用的插件。

部分 UI 组件可以复用或定制，如对话框、列表、输入框等。

### **5.3 改造能力**

重点改造为小说创作场景，包括项目面板、章节树、角色卡、世界观库、剧情分支树、写作指令面板和发布入口。

项目面板从代码项目列表改造为小说项目卡片，展示项目名称、状态、进度和最近活动。

章节树从代码文件树改造为章节目录，支持拖拽排序、状态标记和批量操作。

角色卡界面需要重新设计，提供角色信息的结构化编辑和关系可视化。

世界观库需要新的 UI 来管理地点、势力、物品等设定条目，支持分类和检索。

剧情分支树是新增的核心功能，需要设计可视化界面来展示和编辑分支结构。

写作指令面板需要集成 AI 调用接口，提供续写、改写、扩写等操作的快捷入口。

发布入口需要设计同步界面，展示待发布内容、发布状态和错误处理。

### **5.4 移除或隐藏能力**

隐藏与代码开发强相关但小说创作者不需要的界面元素，降低工具感和认知负担。

隐藏代码相关的菜单项，如构建、运行、调试等。

隐藏 Git 操作界面，但保留底层的版本管理能力供高级用户使用。

隐藏终端面板，替换为创作日志面板，展示 AI 生成过程和提示词。

隐藏 LSP 相关功能，因为小说创作不需要代码补全和语法检查。

隐藏插件市场中的开发工具插件，只展示与创作相关的插件。

隐藏复杂的配置选项，提供简化的偏好设置界面。

### **5.5 插件化扩展点**

设计小说插件、分支剧情插件、同步发布插件、内容检查插件、模型路由插件等扩展点。

小说插件提供基础的章节编辑和 AI 生成能力，是核心功能模块。

分支剧情插件提供分支节点的创建、连接、编辑和可视化能力。

同步发布插件提供与主产品后端的同步能力，包括登录、绑定、发布等功能。

内容检查插件提供角色一致性检查、世界观冲突检测等质量保障能力。

模型路由插件提供模型选择、路由策略、成本控制等 AI 调度能力。

### **5.6 Fork 维护策略**

锁定当前稳定版本，MVP 阶段不追上游新特性，只做最小可控改造。

在 OpenCode 的稳定版本上创建 fork，建立独立的分支进行二次开发。

MVP 开发期间冻结上游更新，专注于编辑器的功能开发和稳定性打磨。

后续按季度评估是否合并上游更新，优先考虑安全补丁和关键功能改进。

维护独立的依赖版本管理，确保二次开发的代码不受上游 breaking changes 影响。

## **第六章 · Agent 架构设计**

### **6.1 Agent 分工原则**

Claude Code Agent 作为主力执行 Agent，负责复杂任务执行、长上下文处理、文件级修改、章节生成和一致性检查。OpenCode Agent 作为补充，负责轻量任务、快速问答、辅助改写和 UI 内嵌提示。

这种双 Agent 架构平衡了能力和效率。主力 Agent 具备更强的推理和生成能力，适合处理复杂任务；补充 Agent 响应更快、成本更低，适合处理高频轻量任务。

### **6.2 主力 Agent 能力范围**

主力 Agent 负责大纲生成、章节扩写、章节改写、角色一致性检查、世界观冲突检查、分支剧情生成和批量任务执行。

大纲生成根据项目设定和已有章节生成后续故事大纲，支持单章大纲或段落大纲。

章节扩写将简略内容或要点扩展为完整的叙事段落，保持风格和节奏的一致性。

章节改写按照指定要求重新组织内容，如调整叙事视角、改变语气风格、简化或深化描写。

角色一致性检查扫描章节内容，识别与角色设定不符的言行举止，标记潜在冲突。

世界观冲突检查验证内容是否符合已建立的世界观规则，识别矛盾和错误。

分支剧情生成基于当前章节和选择上下文，生成符合逻辑的分支内容和选项。

批量任务执行支持按顺序执行多个 AI 任务，适合系列章节的批量生成。

### **6.3 补充 Agent 能力范围**

补充 Agent 负责局部润色、标题建议、摘要生成、标签生成、选项文案优化和轻量 prompt 交互。

局部润色对选中的段落进行语言优化，提升文字质量而不改变内容。

标题建议根据章节内容生成多个可选标题，供创作者参考选择。

摘要生成提取章节的核心要点，生成简洁的章节简介或剧情梗概。

标签生成为章节或分支生成合适的标签，支持分类检索和推荐。

选项文案优化对分支选择或问答选项进行语言润色，提升可读性和吸引力。

轻量 prompt 交互回答创作者的即时问题，如"这个情节合理吗"、"角色应该怎么做"。

### **6.4 Agent 调度策略**

根据任务类型、上下文长度、执行风险和成本选择不同 Agent。

任务类型是首要考虑因素。续写、扩写、改写等核心生成任务交给主力 Agent；润色、摘要等辅助任务交给补充 Agent。

上下文长度影响效率。短上下文任务（小于 4K tokens）可以交给补充 Agent 快速处理；长上下文任务交给主力 Agent。

执行风险影响稳定性。高风险操作（如批量删除、大段改写）交给主力 Agent，因为其具备更好的上下文理解和规划能力。

成本控制影响经济性。补充 Agent 的成本通常低于主力 Agent，适合处理大量轻量任务。

### **6.5 Agent 工具白名单**

MVP 只开放安全工具，例如读取项目文件、写入章节文件、编辑指定文件、搜索项目内文本、读取角色卡、读取世界观设定、写入 AI 日志。

读取项目文件允许 Agent 获取项目结构和基本信息。

写入章节文件允许 Agent 生成或更新章节内容。

编辑指定文件允许 Agent 修改角色卡、世界观设定等配置文件。

搜索项目内文本允许 Agent 在项目范围内查找相关内容。

读取角色卡和世界观设定为 AI 生成提供上下文信息。

写入 AI 日志记录生成过程和结果，便于追溯和优化。

### **6.6 Agent 工具黑名单**

默认禁止执行系统命令、访问项目外文件、任意网络请求、读取环境变量、批量删除文件等高风险操作。

系统命令（如 rm -rf、format）可能导致灾难性后果，必须禁止。

项目外文件访问可能导致数据泄露，必须限制在项目目录内。

任意网络请求可能被滥用，必须通过白名单机制控制。

环境变量可能包含敏感信息，必须禁止读取。

批量删除文件风险极高，必须禁止或需要用户确认。

### **6.7 Agent 日志与可追溯性**

所有 AI 调用、工具调用、文件修改、失败重试和同步行为都要写入本地日志，关键事件同步到后台审计。

AI 调用日志记录每次调用的请求内容、响应内容、耗时、成本和结果评分。

工具调用日志记录 Agent 执行的每个工具调用，包括输入参数和输出结果。

文件修改日志记录 Agent 对文件的修改操作，支持版本对比和回滚。

失败重试日志记录任务失败的详细原因和重试过程。

同步行为日志记录与后端的所有交互，支持异常排查。

## **第七章 · 多沙箱设计**

### **7.1 沙箱定义**

沙箱是一个独立的工作目录、上下文环境和版本空间，用于隔离不同创作方案。

工作目录隔离确保每个沙箱拥有独立的文件存储，互不干扰。

上下文环境隔离确保 AI 在生成内容时只看到当前沙箱内的内容，不会意外引用其他沙箱的信息。

版本空间隔离确保每个沙箱维护独立的版本历史，可以独立回滚和恢复。

### **7.2 沙箱与项目关系**

一个项目可以包含多个沙箱。每个沙箱可以代表主线版本、实验版本、暗线版本、重写版本或不同风格版本。

主线沙箱包含经过审核确认的正式内容，是发布的来源。

实验沙箱用于探索新的情节方向或写作风格，不影响主线进度。

暗线沙箱用于创作与主线关联但独立的故事线。

重写沙箱用于对已有章节进行大幅度修改或重写。

风格沙箱用于尝试不同的写作风格或目标读者定位。

### **7.3 Git Worktree 集成**

使用 worktree 思路管理多个沙箱，让不同版本的内容互不污染，并支持回滚、对比和摘取。

每个沙箱对应一个 Git worktree，共享同一个仓库的历史和基础内容。

沙箱的创建、切换、合并和删除对应 worktree 的添加、检出、删除操作。

分支管理利用 Git 的分支能力支持沙箱版本的独立演进。

对比工具可以比较不同沙箱的内容差异，支持选择性摘取和合并。

### **7.4 沙箱生命周期**

包括创建沙箱、复制沙箱、切换沙箱、重命名沙箱、归档沙箱、删除沙箱和从沙箱发布内容。

创建沙箱时可以选择从主线复制、从模板创建或从备份恢复。

复制沙箱创建现有沙箱的完整副本，用于分支探索。

切换沙箱变更当前工作环境，所有操作在目标沙箱中执行。

重命名沙箱更新沙箱名称和显示标签，不影响内部内容。

归档沙箱将不再活跃的沙箱标记为只读，保留完整内容供后续参考。

删除沙箱移除沙箱的所有文件和版本历史，需要二次确认。

从沙箱发布将选定内容合并回主线，触发审核和发布流程。

### **7.5 沙箱隔离边界**

Agent 只能访问当前沙箱目录，不能跨沙箱读取或写入。跨沙箱内容借用必须通过明确的用户操作触发。

这种隔离机制确保创意探索的灵活性与主线内容的安全性并存。创作者可以在实验沙箱中大胆尝试，而不用担心意外破坏主线内容。

### **7.6 MVP 降级方案**

如果 worktree 集成在第一周 PoC 中失败，则降级为普通目录复制方案，先保证多版本隔离能力。

降级方案使用文件系统目录作为沙箱边界，通过复制实现版本隔离。虽然不如 worktree 优雅，但能够满足基本的多版本管理需求，且实现复杂度更低。

## **第八章 · 多分支剧情设计**

### **8.1 分支剧情定义**

分支剧情是读者在阅读中基于选择、问答或条件进入不同叙事路径的结构。

互动小说的核心特征是读者参与决策影响故事走向。分支剧情设计决定了读者可以选择什么、在什么节点选择、选择后通向哪里。

### **8.2 分支与沙箱的关系**

沙箱是创作环境隔离，分支是故事结构。一个沙箱内可以包含多个剧情分支，二者不是同一个概念。

一个项目可以有主线、暗线、番外等多个沙箱，每个沙箱内部又包含多个分支剧情。沙箱定义了创作的物理隔离，分支定义了故事的叙事结构。

### **8.3 分支 DAG 模型**

分支剧情采用有向无环图结构。节点代表章节或剧情片段，边代表用户选择、问答结果或条件判断。

DAG 结构确保故事逻辑的清晰性，避免循环依赖和逻辑死锁。每个节点有零个或多个前驱节点（入边），零个或多个后继节点（出边）。

### **8.4 分支节点类型**

包括普通章节节点、选择节点、问答节点、隐藏节点、汇合节点和结局节点。

普通章节节点是基本的叙事单元，包含章节内容和指向下一个节点的边。

选择节点为读者提供多个选项，每个选项通向不同的后续节点。

问答节点要求读者回答问题，根据答案判断通向哪个后续节点。

隐藏节点是读者不可见但影响分支逻辑的中间节点，如变量设置、条件判断。

汇合节点是多个分支路径汇聚的节点，不同选择最终到达同一节点。

结局节点是故事的终点，没有出边，可以是单一结局或多个不同结局。

### **8.5 分支编辑能力**

创作者可以新增节点、连接节点、设置选项、设置进入条件、编辑节点内容、删除无效分支、合并分支路径。

新增节点时选择节点类型，指定节点内容或关联章节。

连接节点时选择源节点和目标节点，设置连接的条件或选项文案。

设置选项时编辑选项文字、设置选项效果（如增减属性、设置变量）。

设置进入条件时定义触发该分支所需的前置条件。

编辑节点内容时关联或创建章节内容，设置节点样式和标签。

删除分支时选择节点或边，确认后移除并调整相关连接。

合并路径时选择两个汇合点，定义合并逻辑和保留内容。

### **8.6 分支可视化能力**

MVP 提供基础树状视图或列表视图，v1.1 再增强为完整画布式 DAG 编辑器。

树状视图将分支结构以树形方式展示，适合查看线性叙事和简单分支。

列表视图以表格方式展示所有节点和连接，适合批量管理和数据化操作。

画布式编辑器提供拖拽式节点操作、缩放平移、路径高亮等高级功能。

### **8.7 与主产品问答分支的映射**

编辑器内的分支节点需要能同步到主产品已有的问答分支模型，保证读者端可以直接消费。

同步时需要将编辑器的节点结构转换为后端 API 要求的格式，包括节点 ID、内容、选项、条件和跳转关系。

## **第九章 · 小说创作核心功能**

### **9.1 项目管理**

支持创建项目、绑定圈子、设置语言、设置题材、设置目标读者、配置默认 AI 风格。

创建项目时输入项目名称、描述、绑定的圈子（可选）和目标语言。

项目设置中可以调整语言（英语、中文等）、题材（奇幻、科幻、言情等）、目标读者年龄段、AI 生成风格（简洁、华丽、悬疑等）。

### **9.2 章节管理**

支持章节列表、章节状态、章节排序、章节草稿、章节版本、章节摘要和章节发布状态。

章节状态包括草稿、修改中、待审核、已审核、已发布等。

章节排序支持拖拽调整章节顺序，支持按编号或权重排序。

章节版本记录每次修改的历史，支持版本对比和回滚。

章节摘要由 AI 自动生成或手动编辑，用于快速了解章节内容。

### **9.3 富文本或 Markdown 编辑**

MVP 优先使用 Markdown，保证 AI 读写简单、文件结构清晰、版本管理方便。

Markdown 的优势包括纯文本格式便于版本控制、AI 易于理解和生成、结构简单且可扩展。

编辑器提供 Markdown 实时预览，支持常用格式快捷键和扩展语法。

### **9.4 角色卡管理**

支持角色名称、身份、性格、目标、关系、口癖、禁忌设定和出场章节。

角色基本信息包括名称、别名、头像（可选）、简介。

角色设定包括性格特征（如内向、外向）、行为动机、背景故事、语言风格。

角色关系定义本角色与其他角色的关系（朋友、敌人、爱人等）和关系描述。

出场章节记录角色在哪些章节中出现，便于追踪角色戏份。

### **9.5 世界观设定库**

支持地点、势力、物品、规则、时间线、异兽设定和文化背景设定。

地点设定包括地理名称、描述、特点、关联角色和事件。

势力设定包括组织名称、首领、成员、目标、势力关系。

物品设定包括物品名称、描述、功能、稀有度、关联角色。

规则设定包括世界运行的基本规则、魔法系统、能力限制等。

时间线设定记录故事中的重要事件和发生顺序。

异兽设定是卡牌物语的核心，包括异兽名称、属性、技能、背景故事。

文化背景设定包括种族文化、社会制度、风俗习惯、语言特色。

### **9.6 AI 续写**

基于当前章节、角色卡和世界观继续生成后续内容。

续写时输入当前章节末尾内容，选择续写长度（短、中、长）和风格匹配度。

AI 参考角色设定确保续写内容符合角色性格，参考世界观设定确保符合世界规则。

### **9.7 AI 改写**

支持按风格、节奏、语气、长度、读者年龄段进行改写。

风格改写可以调整为简洁、华丽、悬疑、幽默等不同风格。

节奏改写可以调整叙事节奏，如加快剧情、放缓节奏、增加转折。

语气改写可以调整叙事视角或情感基调，如第一人称、第三人称、客观叙述。

长度改写可以调整目标字数，如扩写压缩、缩写扩展。

年龄段改写调整内容复杂度，如儿童版、青少年版、成人版。

### **9.8 AI 扩写**

将大纲、剧情点或短段落扩写为完整章节。

扩写时输入简略的大纲或要点列表，选择章节长度目标。

AI 负责补充细节、丰富描写、连贯叙事，生成符合质量标准的完整章节。

### **9.9 AI 摘要与标签**

自动生成章节摘要、角色出场列表、剧情标签、分支标签和发布简介。

章节摘要概括本章核心情节，便于快速回顾和推荐。

角色出场列表列出本章出现的所有角色及其戏份权重。

剧情标签标记本章涉及的主题、类型、元素，如"战斗"、"爱情"、"悬疑"。

分支标签标记本章的分支类型，如"选择节点"、"结局分支"、"关键抉择"。

发布简介用于在平台展示本章内容，吸引读者点击阅读。

### **9.10 一致性检查**

检查角色设定冲突、时间线冲突、世界观冲突、前后文矛盾和分支断裂。

角色设定冲突检查本章中角色的言行是否符合已建立的性格设定，是否出现设定外的行为。

时间线冲突检查事件的先后顺序是否矛盾，时间标注是否一致。

世界观冲突检查本章内容是否与已建立的世界规则冲突，如魔法使用、资源消耗等。

前后文矛盾检查本章内容是否与前文描述矛盾，如人物状态、场景描写等。

分支断裂检查分支节点的连接是否完整，是否存在孤立节点或死链。

## **第十章 · AI 工作流引擎**

### **10.1 工作流定位**

工作流用于把多个 AI 操作串成稳定流程，例如"大纲 → 扩写 → 检查 → 修订 → 摘要 → 待发布"。

工作流的价值在于将复杂的创作流程标准化和自动化，减少重复操作，提升创作效率，确保质量一致性。

### **10.2 MVP 内置工作流**

MVP 内置 5 个基础工作流：大纲生成、章节扩写、章节润色、一致性检查、分支剧情生成。

大纲生成工作流从项目设定和已有内容生成后续故事大纲，包括章节标题、核心情节、关键转折。

章节扩写工作流将大纲或要点扩展为完整章节，经过质量检查后进入待审核状态。

章节润色工作流对已有关键章节进行语言优化，提升文字质量和阅读体验。

一致性检查工作流对选定章节进行全方位一致性检查，生成问题报告供创作者处理。

分支剧情生成工作流基于当前节点和选择上下文生成合理的分支内容和选项。

### **10.3 工作流执行模式**

支持手动执行、单章节执行、批量章节执行和中断恢复。

手动执行由用户触发每个步骤，适合需要人工审核的环节。

单章节执行针对单个章节执行完整工作流，适合日常创作。

批量章节执行对多个章节依次执行工作流，适合批量生产。

中断恢复在工作流执行中断后从断点继续，无需从头开始。

### **10.4 工作流状态管理**

每个任务需要记录等待中、执行中，成功、失败、已取消和需人工确认等状态。

等待中表示任务已提交但尚未开始执行。

执行中表示任务正在进行中，可能有进度信息。

成功表示任务正常完成，结果已保存。

失败表示任务执行出错，可能有错误信息和重试选项。

已取消表示用户主动取消了任务。

需人工确认表示任务暂停等待用户决策，如选择修改方案或确认继续。

### **10.5 失败重试机制**

模型失败、超时、返回格式错误、工具调用失败时，需要有明确的重试和降级策略。

模型失败时等待一段时间后重试，如果连续失败则切换到备用模型或降级方案。

超时错误时根据上下文判断是否继续生成，可能需要分段处理长文本。

格式错误时记录错误样本，调整 prompt 后重试。

工具调用失败时检查文件状态和权限，可能需要用户干预。

### **10.6 MVP 降级方案**

如果完整工作流引擎超出工期，则先做固定模板按钮，不开放自定义 DSL。

降级方案提供预设的工作流模板，用户选择模板后一键执行，不支持自定义步骤和参数。

## **第十一章 · 本地数据与文件模型**

### **11.1 本地存储原则**

采用 local-first，所有创作内容优先保存在本地，发布时再同步到服务端。

本地存储的优势包括离线可用、数据主权、快速响应、无同步冲突。编辑器不需要时刻保持网络连接，创作者可以在任何环境下工作。

### **11.2 文件目录结构**

定义项目目录、沙箱目录、章节目录、角色卡文件、世界观文件、分支文件、日志文件和配置文件。

项目根目录下包含项目配置文件、多个沙箱目录和共享资源目录。

每个沙箱目录下包含章节目录、角色卡目录、世界观目录和分支定义文件。

日志目录记录 AI 调用、操作历史和同步记录。配置目录包含编辑器设置和偏好配置。

### **11.3 SQLite 数据表**

设计 projects、sandboxes、chapters、characters、world_settings、branch_nodes、branch_edges、ai_tasks、ai_logs、sync_records 等表。

projects 表存储项目基本信息、配置和状态。

sandboxes 表存储沙箱信息、所属项目和创建时间。

chapters 表存储章节元数据、内容路径、状态和版本信息。

characters 表存储角色卡信息和关联项目。

world_settings 表存储世界观条目和分类。

branch_nodes 表存储分支节点信息。

branch_edges 表存储节点间的连接关系。

ai_tasks 表存储 AI 任务记录和状态。

ai_logs 表存储 AI 调用的详细日志。

sync_records 表存储同步操作的记录和状态。

### **11.4 Markdown / JSON 文件规范**

章节正文使用 Markdown，结构化数据使用 JSON 或 SQLite，保证 Agent 易读易写。

Markdown 章节文件的元数据通过 frontmatter 格式存储，包括章节标题、状态、标签等信息。

JSON 文件用于存储角色卡、世界观条目、分支定义等结构化数据，便于程序读取和修改。

### **11.5 版本记录**

每次 AI 修改和人工修改都应产生版本记录，支持对比、回滚和恢复。

版本记录包括修改时间、修改类型（AI/人工）、修改内容和修改原因（可选）。

版本对比支持可视化展示两个版本之间的差异，高亮显示新增、删除和修改的内容。

版本回滚可以将章节恢复到之前的任意版本，支持完整回滚或选择性回滚。

### **11.6 备份与恢复**

支持本地备份、导出项目包、从备份恢复项目。

本地备份定期自动创建，保留最近 N 个备份版本。

导出项目包将整个项目打包为压缩文件，便于转移或分享。

从备份恢复可以选择备份版本进行完整恢复或部分恢复。

## **第十二章 · 后端同步设计**

### **12.1 同步目标**

编辑器只同步"准备发布"的内容，不同步全部草稿和全部沙箱状态。

这种设计减少了不必要的数据传输，降低了服务端存储压力，也避免了草稿内容的过早暴露。

### **12.2 登录认证**

复用已有用户体系，创作者登录后获取访问权限和可绑定圈子列表。

编辑器不维护独立的用户系统，直接调用主产品的认证服务获取令牌。

### **12.3 圈子绑定**

一个项目可以绑定到一个圈子或内容空间，用于后续发布章节和分支内容。

圈子是卡牌物语的内容组织单元，每个圈子有独立的作者、编辑和读者。

### **12.4 章节同步**

将本地章节同步为服务端章节草稿、待发布内容或正式发布内容。

同步前检查本地和远程的内容差异，显示变更预览。

用户确认后执行同步，显示同步进度和结果。

同步冲突时提示用户选择保留版本或进行合并。

### **12.5 分支同步**

将分支节点、选项、条件和剧情片段同步到主产品分支模型。

分支同步需要处理节点 ID 映射，确保本地节点和远程节点正确对应。

### **12.6 资产同步**

用于上传封面、卡牌图、异兽图、音频或其他素材。MVP 可只支持图片上传。

资产上传前进行格式验证和大小限制。

上传后获取资产 URL 并关联到对应内容。

### **12.7 配额同步**

编辑器需要查询创作者剩余 AI 配额、任务次数和同步权限。

每次 AI 调用前检查配额余额，不足时提示用户。

### **12.8 冲突处理**

若服务端内容和本地内容同时变化，MVP 优先采用人工确认覆盖策略，不做复杂自动合并。

冲突时显示两个版本的内容对比，由用户决定保留哪个版本或进行手动合并。

## **第十三章 · 模型网关与成本控制**

### **13.1 模型网关定位**

编辑器不直接暴露模型 Key，所有 AI 请求通过统一模型网关转发、计量、限流和记录。

模型网关屏蔽了具体的模型实现细节，提供统一的 API 接口。

### **13.2 模型路由原则**

根据任务类型、上下文长度、成本、速度和失败率选择不同模型通道。

简单任务（润色、摘要）优先使用快速便宜的模型。

复杂任务（扩写、检查）使用能力强的模型，可能成本更高。

### **13.3 成本控制策略**

通过输入裁剪、上下文摘要、缓存、任务分级、配额上限、失败熔断控制成本。

输入裁剪在发送给模型前移除不必要的上下文，减少 token 消耗。

上下文摘要将长上下文压缩为关键信息，降低每次调用的 token 量。

缓存对相同或相似的请求返回缓存结果，避免重复调用。

任务分级根据任务重要性分配不同的资源预算，高优先级任务可以获得更多重试机会。

配额上限为每个项目、每个用户设置月度 token 上限，超出后限制调用。

失败熔断当某个模型的失败率超过阈值时自动切换到备用模型。

### **13.4 配额模型**

按创作者、项目、任务类型设置月度 token 上限和调用次数上限。

创作者配额是全局上限，由管理员分配。

项目配额是单个项目的用量限制，避免某个项目过度消耗。

任务类型配额限制某类任务（如批量生成）的调用次数。

### **13.5 失败回退**

当默认通道失败时，按预设顺序回退到备用通道；高成本通道只在必要任务中启用。

回退顺序通常是从主力模型到轻量模型，从云端模型到本地模型。

### **13.6 调用审计**

记录请求时间、任务类型、输入规模、输出规模、成本估算、失败原因和最终结果。

审计日志支持成本分析、性能优化和问题排查。

## **第十四章 · 权限、安全与内容治理**

### **14.1 账号权限**

只支持邀请制账号。普通创作者、内部编辑、管理员拥有不同权限。

普通创作者可以创建和管理自己的项目，调用 AI 生成内容，同步内容到绑定的圈子。

内部编辑可以管理自己负责的项目，可以审核其他创作者的内容。

管理员拥有全部权限，可以邀请创作者、分配配额、查看审计日志、处理异常。

### **14.2 本地文件安全**

限制 Agent 的文件访问范围，避免读取系统目录、其他项目目录或敏感配置文件。

Agent 只能访问当前沙箱目录和明确定义的共享资源。

沙箱边界通过文件系统权限和程序层面的路径检查双重保障。

### **14.3 Key 安全**

所有模型 Key 存放在服务端或模型网关，客户端不保存高权限 Key。

客户端只保存访问令牌，令牌有过期时间和权限范围。

### **14.4 操作审计**

关键操作包括登录、创建项目、调用 AI、修改章节、删除沙箱、同步发布和配额异常。

审计日志记录操作人、操作时间、操作内容和操作结果。

管理员可以查看和导出审计日志。

### **14.5 内容分级策略**

编辑器 MVP 不做复杂内容审核，但需要保留内容分级标记、发布前确认、日志留存和管理员追溯能力。

内容分级标记如"全年龄"、"13+"、"18+"等，在同步时传递到主产品。

发布前确认要求创作者确认内容符合平台规范。

日志留存确保所有内容修改都有记录可查。

管理员追溯能力允许管理员查看任意内容的历史版本和修改记录。

### **14.6 滥用防护**

通过速率限制、配额限制、异常调用检测和账号冻结保护系统。

速率限制防止短时间内大量请求压垮系统。

配额限制控制单个账号的资源消耗。

异常调用检测识别可能的滥用行为，如频繁的失败尝试、异常的调用模式等。

账号冻结在确认滥用后暂停账号访问，需要管理员解封。

## **第十五章 · UI 与交互设计大纲**

### **15.1 主界面布局**

采用左侧项目与章节树，中间编辑区，右侧 AI 面板和设定面板，下方日志与任务状态栏的结构。

左侧栏展示项目列表、当前项目的沙箱选择和章节目录树。

中间编辑区是主要的创作空间，提供章节内容编辑、分支可视化等能力。

右侧面板提供 AI 操作入口（续写、改写、扩写等）和角色/世界观快速访问。

底部状态栏显示当前任务状态、AI 配额、同步状态和通知消息。

### **15.2 项目首页**

展示项目状态、绑定圈子、最近章节、AI 配额、待处理任务和同步状态。

项目状态显示项目的整体进度和健康度。

绑定圈子显示当前绑定的圈子信息和切换入口。

最近章节展示最近编辑或生成的章节。

AI 配额显示剩余 token 额度和消耗趋势。

待处理任务显示需要人工处理的任务数量和类型。

同步状态显示上次同步时间和是否有待同步内容。

### **15.3 章节编辑页**

提供正文编辑、AI 指令、版本记录、摘要、发布状态和关联分支入口。

正文编辑区支持 Markdown 编写和实时预览。

AI 指令区提供续写、改写、扩写等快捷操作按钮。

版本记录展示章节的修改历史，支持版本对比。

摘要区显示 AI 自动生成的章节摘要。

发布状态显示章节的审核状态和发布状态。

关联分支入口显示本章关联的分支节点，支持快速跳转。

### **15.4 角色卡页面**

支持角色列表、角色详情、关系备注和 Agent 上下文引用。

角色列表以卡片形式展示所有角色，支持筛选和搜索。

角色详情展示角色的完整设定信息，支持编辑和版本管理。

关系备注以图谱形式展示角色之间的关系，支持拖拽调整。

Agent 上下文引用提供"引用到当前章节"的功能，方便 AI 生成时获取角色信息。

### **15.5 世界观页面**

支持设定分类、检索、引用和冲突检查。

设定分类将世界观条目按照类型组织，如地点、势力、物品等。

检索功能支持按名称、内容和标签搜索。

引用功能提供"插入到章节"的能力，支持 AI 生成时参考。

冲突检查入口调用一致性检查，扫描可能存在的世界观冲突。

### **15.6 分支剧情页面**

MVP 采用基础树状视图或表格视图，支持创建节点、连接节点、编辑选项和预览路径。

树状视图以树形结构展示分支拓扑，支持展开折叠和拖拽操作。

表格视图以数据表形式展示所有节点和连接，支持批量编辑。

创建节点入口提供新增节点的快捷方式。

预览路径功能模拟读者选择过程，验证分支逻辑的正确性。

### **15.7 AI 任务面板**

展示当前任务、历史任务、失败任务、重试按钮和输出结果。

当前任务区显示正在执行的任务及其进度。

历史任务区展示已完成的任务列表，支持查看详情和结果。

失败任务区高亮显示失败的任务，提供错误信息和重试按钮。

### **15.8 同步发布面板**

展示待发布章节、分支节点、资产列表、校验结果和发布按钮。

待发布区列出所有待同步的内容，支持选择和取消。

分支节点区显示待同步的分支结构。

资产列表区显示待上传的素材及上传状态。

校验结果区显示同步前的检查结果，如发现问题需要先处理。

发布按钮触发同步操作，显示同步进度和最终结果。

## **第十六章 · API 与协议设计大纲**

### **16.1 编辑器到后端 API**

包括登录、获取圈子、同步章节、同步分支、上传资产、查询配额、提交发布、查询发布状态。

登录 API 验证用户凭证，返回访问令牌和用户信息。

获取圈子 API 返回用户可访问的圈子列表和详情。

同步章节 API 提交章节内容和元数据到服务端。

同步分支 API 提交分支节点和连接关系到服务端。

上传资产 API 上传二进制文件，返回资产 URL。

查询配额 API 获取当前配额余额和使用情况。

提交发布 API 将章节标记为待发布或直接发布。

查询发布状态 API 获取内容的发布状态和历史。

### **16.2 编辑器到模型网关 API**

包括普通生成、结构化生成、长文本检查、批量任务、流式响应和调用记录。

普通生成 API 发送文本 prompt，返回生成的文本内容。

结构化生成 API 生成符合指定 JSON Schema 的结构化输出。

长文本检查 API 对章节内容进行一致性检查，返回问题报告。

批量任务 API 提交多个生成任务，返回任务 ID 用于查询结果。

流式响应 API 支持 Server-Sent Events，实现打字机效果的流式输出。

调用记录 API 查询历史调用记录和统计数据。

### **16.3 编辑器内部 Agent RPC**

定义 UI 层与 Agent 层之间的任务提交、任务取消、任务状态查询、工具调用结果返回等协议。

任务提交协议定义任务类型、参数、超时设置和回调配置。

任务取消协议定义任务 ID 和取消原因。

状态查询协议返回当前任务状态、进度和中间结果。

工具调用协议定义工具名称、参数和权限要求。

结果返回协议定义成功结果和错误信息的格式。

### **16.4 数据结构规范**

定义 Project、Sandbox、Chapter、Character、WorldSetting、BranchNode、BranchEdge、AITask、SyncRecord 等核心对象。

Project 对象包含项目 ID、名称、描述、圈子 ID、配置和创建时间。

Sandbox 对象包含沙箱 ID、名称、所属项目、状态和创建时间。

Chapter 对象包含章节 ID、标题、内容路径、状态、版本和排序权重。

Character 对象包含角色 ID、名称、设定 JSON、关联项目和状态。

WorldSetting 对象包含设定 ID、类型、名称、内容、关联项目。

BranchNode 对象包含节点 ID、类型、内容、章节 ID 和元数据。

BranchEdge 对象包含边 ID、源节点 ID、目标节点 ID、条件和选项。

AITask 对象包含任务 ID、类型、参数、状态、结果和执行时间。

SyncRecord 对象包含同步 ID、类型、内容 ID、同步时间和状态。

### **16.5 错误码规范**

覆盖认证失败、权限不足、配额不足、模型失败、同步冲突、文件访问失败、任务超时等错误类型。

认证失败错误码用于令牌无效、过期或被撤销的情况。

权限不足错误码用于当前用户无权执行操作的情况。

配额不足错误码用于 token 或调用次数超限的情况。

模型失败错误码用于 AI 模型调用出错的情况，包含具体错误原因。

同步冲突错误码用于服务端内容已变化需要处理的情况。

文件访问失败错误码用于文件不存在、权限不足或格式错误的情况。

任务超时错误码用于任务执行时间超过限制的情况。

## **第十八章 · 验收标准**

### **18.1 功能验收**

验证项目创建、章节生成、章节编辑、角色卡、世界观、分支节点、AI 检查、沙箱隔离、同步发布是否全部跑通。

每个功能点都需要设计具体的验收用例，明确输入、预期输出和判定标准。

### **18.2 性能验收**

验证启动速度、章节打开速度、AI 首 token 响应、章节保存速度、同步耗时和大项目加载表现。

具体指标需要根据实际硬件环境和用户期望设定，通常启动时间不超过 5 秒，AI 首 token 响应不超过 3 秒。

### **18.3 稳定性验收**

连续使用两周，无严重数据丢失，无无法恢复的任务失败，无 Agent 越权访问。

严重数据丢失指丢失超过 1 小时的工作成果；无法恢复的任务失败指任务卡死无法中断或重试；Agent 越权访问指 Agent 访问了沙箱边界外的内容。

### **18.4 内容生产验收**

内部团队使用编辑器完成卡牌物语 MVP 所需的首批内容：至少 10 章英文互动内容、30 张异兽卡牌文案、20 个问答/选择分支节点。

这是最终的业务验收指标，验证编辑器能够支撑实际的内容生产需求。

### **18.5 同步验收**

编辑器生成内容能够成功进入主产品测试环境，并被读者端正确渲染。

同步验收包括内容同步成功、分支逻辑正确渲染、读者体验流畅等多个方面。

## **第十九章 · 风险与降级方案**

### **19.1 OpenCode 二开风险**

如果代码结构复杂、构建困难或改造成本超预期，则优先保留核心能力，减少 UI 重塑。

降级策略是保持 OpenCode 原生 UI，只在核心逻辑层做定制，减少前端改造工作量。

### **19.2 主力 Agent 集成风险**

如果主力 Agent 集成不稳定，则先使用命令行子进程方式接入，UI 层只做任务提交和结果展示。

降级方案绕过了 Agent SDK 的复杂性，用简单的进程调用实现 AI 能力。

### **19.3 多沙箱风险**

如果 worktree 方案延期，则降级为目录复制方案。

降级方案虽然功能不如 worktree 强大，但实现简单可靠，能够满足基本的多版本管理需求。

### **19.4 分支可视化风险**

如果画布式分支编辑成本过高，则降级为树状列表和表格编辑。

降级方案功能受限但实现成本低，能够保证分支编辑的核心能力。

### **19.5 工作流引擎风险**

如果自定义工作流超期，则降级为固定模板按钮。

降级方案将工作流简化为预设模板，用户不能自定义但可以使用标准流程。

### **19.6 同步冲突风险**

如果自动合并复杂度过高，则采用人工确认覆盖策略。

降级方案不提供自动合并，用户手动决定保留哪个版本。

### **19.7 AI 成本风险**

如果调用成本超过预算，则降低默认上下文、限制批量任务、启用摘要缓存和月度配额。

降级方案通过多种手段控制成本，包括技术优化和运营策略。

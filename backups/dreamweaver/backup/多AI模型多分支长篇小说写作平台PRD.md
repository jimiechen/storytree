## 1. 产品概述

### 1.1 产品名称

**「织梦笔」**（暂定名，英文名：DreamWeaver AI）

> 名称寓意：以多AI模型为经线，以多分支叙事为纬线，编织长篇小说的宏大叙事之梦。

### 1.2 产品愿景

打造全球首个**多AI模型协作 × 多分支叙事管理 × 百万字级长篇一致性保持**三位一体的小说创作平台，让每位创作者都能拥有一个由多个AI助手组成的"虚拟创作团队"，实现真正的人机共创。

### 1.3 一句话描述

一个支持接入多个AI大模型、可视化管理故事分支、智能保持百万字级长篇一致性的长篇小说创作平台，面向中文个人创作者，提供从灵感到成稿的全链路AI辅助写作体验。

### 1.4 核心问题

| 编号 | 痛点 | 严重程度 | 现有解决方案 | 未满足之处 |
|------|------|---------|-------------|-----------|
| P1 | 长篇小说（10万字+）角色/情节一致性崩溃 | ⭐⭐⭐⭐⭐ | 手动维护笔记、反复提示词 | 效率极低，仍频繁出错 |
| P2 | 不同AI模型各有所长，但无法协同使用 | ⭐⭐⭐⭐ | 手动复制粘贴切换模型 | 上下文断裂，风格割裂 |
| P3 | 想探索"如果当初……"的故事分支，但无法管理 | ⭐⭐⭐⭐ | 手动另存副本 | 文件混乱，无法可视化 |
| P4 | AI生成文本"AI味"重，被平台检测拒稿 | ⭐⭐⭐⭐ | 人工逐句修改 | 耗时巨大，违背AI辅助初衷 |
| P5 | 中文特色题材（仙侠/古风/权谋）AI理解差 | ⭐⭐⭐ | 使用国产模型 | 国产模型创意写作能力有限 |
| P6 | 从灵感到发布缺乏全链路工具 | ⭐⭐⭐ | 多工具拼接 | 体验割裂，效率低下 |

### 1.5 产品目标

| 维度 | 目标 | 衡量标准 |
|------|------|---------|
| 用户增长 | 上线6个月注册用户达10万 | MAU、注册转化率 |
| 用户活跃 | 日活用户创作时长≥30分钟 | 平均会话时长、创作字数/日 |
| 内容产出 | 平台累计产出长篇小说≥5000部 | 作品数、平均字数 |
| 用户留存 | 30日留存率≥40% | 次日/7日/30日留存 |
| 付费转化 | 付费转化率≥8% | 付费用户占比、ARPU |

### 2.4 市场机会

1. **蓝海空白**：目前全球没有任何平台同时具备"多模型协作 + 分支叙事管理 + 长篇一致性保持"三大核心能力
2. **中文市场缺口**：国际平台（AI Dungeon、NovelAI）几乎不支持中文；国内平台缺乏分支叙事和长篇管理能力
3. **技术窗口期**：RAG技术成熟 + 国产大模型能力飞跃 + 向量数据库成本下降，使得百万字级一致性方案首次具备可行性
4. **用户心智红利**：AI写作概念已普及，用户从"好奇尝试"进入"深度使用"阶段，愿意为专业工具付费

## 4. 产品定位与核心价值主张

### 4.1 产品定位

**「织梦笔」定位为面向中文个人创作者的专业级AI小说创作平台**，以"多模型协作引擎"为核心技术壁垒，以"分支叙事管理"为差异化功能，以"百万字级长篇一致性"为品质保障。

### 4.2 核心价值主张

> **"让每个创作者都拥有一个AI创作团队"**

| 价值维度 | 传统方式 | 竞品方案 | 织梦笔方案 |
|---------|---------|---------|-----------|
| 模型选择 | 单一模型，风格受限 | 部分支持多模型切换 | 多模型**协作流水线**，自动分配任务 |
| 分支探索 | 手动另存副本 | 简单Undo/Redo | **可视化分支树**，支持分支合并 |
| 长篇一致 | 手动笔记维护 | 有限上下文窗口 | **RAG+知识图谱**，百万字级一致性 |
| 中文创作 | 依赖人工 | 英文平台为主 | **原生中文优化**，支持特色题材 |
| 去AI味 | 人工逐句修改 | 部分支持 | **多模型交叉润色**，自然度评分 |

### 4.3 产品原则

1. **人机共创，而非AI代写**：AI是助手和协作者，人类作者始终掌握最终决策权
2. **模型中立，择优而用**：不绑定特定AI模型，让用户自由选择和组合
3. **长篇优先，一致性为王**：所有功能设计以百万字级长篇创作为核心场景
4. **中文原生，题材包容**：深度优化中文创作体验，覆盖网文/严肃文学/互动小说等全品类
5. **开放生态，插件扩展**：提供开放API和插件系统，允许社区贡献模型适配器和功能扩展

### 5.2 模块一：多模型协作引擎（P0）

#### 5.2.1 模型接入层

**功能描述**：支持接入多个主流AI大模型，用户可自由选择、切换和组合使用。

| 功能项 | 详细说明 | 优先级 |
|--------|---------|--------|
| 内置模型市场 | 预集成 Claude、GPT-4o、Gemini、DeepSeek、通义千问、文心一言、豆包、Kimi、Llama 等主流模型 | P0 |
| BYOK 模式 | 支持用户自带 API Key 接入任意兼容 OpenAI API 格式的模型 | P0 |
| 模型能力标签 | 为每个模型标注擅长领域（如"悬疑推理""古风描写""对话生成""逻辑推演"等） | P0 |
| 模型对比面板 | 同一提示词同时发送给多个模型，并排对比输出结果 | P1 |
| 自定义模型配置 | 调整 temperature、top_p、max_tokens 等参数，保存为预设 | P1 |

**支持的模型列表（首期）**：

| 模型 | 提供商 | 擅长领域 | 接入方式 |
|------|--------|---------|---------|
| Claude 4 Opus | Anthropic | 长文创意写作、文学性表达 | 平台代理 |
| GPT-4o | OpenAI | 逻辑推演、对话生成 | 平台代理/BYOK |
| Gemini 2.5 Pro | Google | 多模态、知识检索 | 平台代理 |
| DeepSeek V3 | 深度求索 | 中文推理、硬科幻 | 平台代理/BYOK |
| 通义千问 Max | 阿里云 | 中文创作、古风题材 | 平台代理/BYOK |
| 文心一言 4.0 | 百度 | 中文理解、商业写作 | 平台代理 |
| Kimi | 月之暗面 | 长文本理解、中文对话 | 平台代理/BYOK |
| Llama 3 | Meta | 英文创作、开源定制 | BYOK |

#### 5.2.2 智能模型路由

**功能描述**：根据创作任务的类型和上下文，自动推荐或分配最适合的AI模型。

| 功能项 | 详细说明 | 优先级 |
|--------|---------|--------|
| 任务类型识别 | 自动识别当前任务类型（扩写/续写/对话/描写/推演/润色等） | P0 |
| 智能模型推荐 | 根据任务类型和上下文，推荐最适合的1-3个模型 | P0 |
| 自动模型切换 | 用户可开启"自动模式"，系统自动为不同任务选择最优模型 | P1 |
| 模型协作流水线 | 配置多步骤流水线，如"DeepSeek构思大纲 → Claude扩写 → 通义千问润色" | P1 |
| 模型偏好记忆 | 记住用户对不同任务类型的模型偏好，持续优化推荐 | P2 |

**模型路由规则示例**：

```
任务：古风场景描写
  → 推荐：通义千问（古风中文最优）> 文心一言 > Claude

任务：悬疑逻辑推演
  → 推荐：DeepSeek（推理最强）> GPT-4o > Claude

任务：角色对话生成
  → 推荐：Claude（对话自然度最高）> GPT-4o > Kimi

任务：长篇续写（保持一致性）
  → 推荐：Claude（200K上下文）> Gemini > GPT-4o
```

#### 5.2.3 多模型协作模式

**功能描述**：支持多个AI模型在同一创作任务中协作，各取所长。

| 协作模式 | 描述 | 使用场景 |
|---------|------|---------|
| **投票模式** | 同一任务发给N个模型，用户选择最佳结果 | 关键情节决策、开头/结尾创作 |
| **接力模式** | 模型A完成第一步 → 结果传给模型B完成第二步 | 大纲→章节→正文流水线 |
| **辩论模式** | 两个模型对同一情节提出不同方案，用户裁决 | 情节走向选择、角色动机分析 |
| **融合模式** | 多个模型的输出经AI融合为统一结果 | 风格混合、多角度描写 |
| **评审模式** | 模型A创作，模型B/C评审并给出修改建议 | 质量把控、一致性检查 |

### 5.3 模块二：分支叙事管理系统（P0）

#### 5.3.1 分支创建与管理

**功能描述**：在创作的任意节点创建故事分支，探索不同的情节走向。

| 功能项 | 详细说明 | 优先级 |
|--------|---------|--------|
| 节点分支 | 在任意段落/章节处创建分支点，生成2-4条备选走向 | P0 |

### 5.4 模块三：长篇管理与一致性引擎（P0）

#### 5.4.1 结构化知识库（Story Bible）

**功能描述**：构建结构化的"故事圣经"数据库，作为AI生成的上下文基础。

| 知识类型 | 字段 | 说明 |
|---------|------|------|
| **角色档案** | 姓名、别名、年龄、外貌、性格、背景、能力、关系、成长弧线、语言风格 | AI生成时自动注入相关角色信息 |
| **地点设定** | 名称、描述、地理关系、历史、特殊规则 | 确保场景描写一致 |
| **物品/道具** | 名称、外观、功能、持有者、获取方式 | 避免道具设定矛盾 |
| **势力/组织** | 名称、成员、目标、规则、势力关系 | 维持世界观逻辑 |
| **时间线** | 事件、时间、涉及角色、影响 | 避免时间线混乱 |
| **伏笔/悬念** | 内容、埋设位置、计划回收位置、状态（已回收/待回收） | 确保伏笔不遗忘 |
| **世界观规则** | 魔法体系/科技设定/社会规则等 | 确保设定不矛盾 |
| **风格指南** | 叙事视角、语言风格、禁忌词汇、参考作品 | 保持文风统一 |

**知识库管理功能**：

| 功能项 | 详细说明 | 优先级 |

| 智能关联 | 自动发现实体间的关系并建立关联 | P1 |

#### 5.4.2 RAG 检索增强生成

**功能描述**：利用向量检索技术，在AI生成时动态注入最相关的上下文信息。

| 功能项 | 详细说明 | 优先级 |
|--------|---------|--------|
| 向量化存储 | 将已写内容和知识库向量化存储 | P0 |
| 语义检索 | 根据当前创作上下文，自动检索最相关的历史内容 | P0 |
| 上下文窗口管理 | 智能管理有限的上下文窗口，优先注入最关键信息 | P0 |
| 多级检索策略 | 近期内容（最近3章）+ 相关角色 + 相关伏笔 + 世界观规则 | P0 |
| 检索结果可调 | 用户可查看和调整AI参考的上下文内容 | P1 |

**上下文注入策略**：

```
┌─────────────────────────────────────────┐
│            AI 上下文窗口分配              │
├──────────────┬──────────────────────────┤
│  系统提示词   │  创作指令 + 风格要求      │  ~10%
├──────────────┼──────────────────────────┤
│  知识库检索   │  相关角色 + 世界观规则     │  ~20%
├──────────────┼──────────────────────────┤
│  历史内容检索 │  相关章节片段 + 伏笔       │  ~30%
├──────────────┼──────────────────────────┤
│  近期上下文   │  最近1-2章完整内容        │  ~30%
├──────────────┼──────────────────────────┤
│  当前任务     │  用户当前的创作指令        │  ~10%
└──────────────┴──────────────────────────┘
```

**一致性检查工作流**：

```
用户提交新内容
      │
      ▼
┌─────────────┐
│  预检查      │ ← 实时检查（输入时）

│  基础设定     │
└──────┬──────┘
       │ 通过
       ▼
┌─────────────┐
│  深度检查    │ ← AI生成后检查

└──────┬──────┘
       │
       ▼
  ┌────┴────┐
  │ 无问题   │ → 自动通过
  ├─────────┤
  │ 有警告   │ → 标记警告，用户决定是否修改
  ├─────────┤
```

```
              │   后处理器        │
              │  (一致性检查+    │
              │   去AI味+格式化)  │
              └────────┬────────┘
                       │
                       ▼
                  返回用户
```

#### 6.3.2 RAG 检索增强流程

```
用户输入创作指令
       │
       ▼
┌──────────────┐
│ 1. 查询理解   │ → 提取关键实体（角色名、地点、事件）
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 2. 多路检索   │
│  ├→ 向量检索  │ → 从已写内容中检索语义相似的段落
│  ├→ 知识库   │ → 检索相关角色/地点/设定条目
│  ├→ 伏笔库   │ → 检索相关未回收伏笔
│  └→ 近期内容  │ → 获取最近1-2章的完整内容
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 3. 上下文组装 │ → 按优先级排序，截断到模型上下文窗口限制
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 4. Prompt构建 │ → 系统提示 + 知识库上下文 + 历史内容 + 用户指令
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 5. 模型推理   │ → 调用选定的AI模型生成内容
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 6. 后处理    │ → 一致性检查 → 去AI味 → 格式化
└──────┬───────┘
       │
       ▼
    返回结果
```

#### 6.3.3 向量化与索引策略

| 内容类型 | 向量化策略 | 索引方式 | 检索优先级 |
|---------|-----------|---------|-----------|
| 章节正文 | 按段落切分（~500 tokens/段），使用 text-embedding-3-large | Milvus IVF_PQ | 中 |
| 角色档案 | 整体向量化 + 关键字段单独索引 | Milvus HNSW | 高 |
| 世界观规则 | 整体向量化 + 关键词索引 | Milvus + ES | 高 |
| 伏笔记录 | 整体向量化 + 关联章节索引 | Milvus | 高 |
| 对话记录 | 按对话轮次切分，标注参与角色 | Milvus | 中 |
| 用户风格样本 | 按段落切分，标注风格特征 | Milvus | 中 |

### 6.5 性能设计

| 指标 | 目标 | 实现方案 |
|------|------|---------|
| AI响应延迟 | ≤3秒（首token） | 流式输出、模型预热、请求队列 |
| 页面加载时间 | ≤1.5秒 | CDN、SSR、懒加载 |
| 向量检索延迟 | ≤200ms | HNSW索引、缓存热点查询 |
| 并发用户 | ≥10万 | Kubernetes弹性伸缩、Redis缓存 |
| 数据可用性 | ≥99.9% | 多副本、自动故障转移、定期备份 |
| 单作品最大字数 | ≥500万字 | 分片存储、增量向量化 |

### 6.6 安全设计

| 安全维度 | 措施 |
|---------|------|
| 用户认证 | JWT + OAuth2.0（微信/Google/GitHub登录） |
| 数据加密 | 传输层TLS 1.3，存储层AES-256加密敏感数据 |
| API安全 | 速率限制、输入验证、CORS策略 |
| 内容安全 | AI生成内容安全过滤（暴力/色情/政治敏感） |
| 数据隔离 | 用户数据逻辑隔离，作品内容加密存储 |
| API Key安全 | BYOK模式下的Key加密存储，不记录明文 |

### 7.4 交互设计要点

#### 7.4.1 AI交互模式

| 交互方式 | 描述 | 适用场景 |
|---------|------|---------|
| **内联补全** | AI在光标位置直接续写，灰色预览，Tab接受 | 日常续写 |
| **侧边栏对话** | 右侧面板与AI对话式交互 | 复杂需求讨论 |
| **选中操作** | 选中文字后弹出AI操作菜单 | 扩写/改写/润色 |
| **快捷指令** | 输入 `/` 触发命令面板 | 快速调用AI功能 |
| **流式输出** | AI生成内容逐字显示，支持中途停止 | 所有AI生成场景 |

#### 7.4.2 核心快捷键

| 快捷键 | 功能 |
|--------|------|
| `Tab` | 接受AI内联补全 |
| `Esc` | 取消AI生成 |
| `Ctrl+Enter` | 手动触发AI续写 |
| `Ctrl+Shift+R` | 改写选中文本 |
| `Ctrl+Shift+E` | 扩写选中文本 |
| `Ctrl+Shift+D` | 去AI味处理 |
| `Ctrl+Shift+B` | 在当前位置创建分支 |
| `Ctrl+/` | 打开命令面板 |
| `Ctrl+Shift+L` | 切换左右面板 |
| `Ctrl+Shift+K` | 切换模型 |
| `Ctrl+S` | 保存（自动保存，手动触发） |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 撤销/重做 |

#### 7.4.3 动效设计

| 场景 | 动效 | 目的 |
|------|------|------|
| AI生成中 | 光标处显示呼吸灯 + 侧边栏显示生成进度 | 反馈AI正在工作 |
| 分支创建 | 节点从当前位置分裂出的动画 | 直观展示分支关系 |
| 一致性警告 | 轻微震动 + 黄色高亮标记 | 引起注意但不打断创作 |
| 模型切换 | 顶部模型图标平滑过渡 | 感知模型变化 |
| 保存成功 | 右下角轻量 toast 提示 | 确认保存状态 |

## 11. 风险评估与应对

### 11.1 技术风险

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| AI模型API不稳定/涨价 | 高 | 高 | 多模型冗余、BYOK模式、缓存常用生成结果 |
| 长文本RAG检索精度不足 | 中 | 高 | 多路检索策略、人工反馈优化、知识图谱辅助 |
| 百万字级性能瓶颈 | 中 | 高 | 分片存储、增量索引、异步处理 |
| AI生成内容质量不稳定 | 高 | 中 | 多模型投票、人工审核机制、质量评分反馈 |

### 11.2 产品风险

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| 用户学习成本高 | 中 | 高 | 渐进式功能披露、新手引导、模板降低门槛 |
| 功能过于复杂导致体验差 | 中 | 高 | 核心功能极简、高级功能折叠、用户测试驱动迭代 |
| 去AI味效果不理想 | 中 | 中 | 多模型交叉改写、持续优化算法、人工精修建议 |

### 11.3 市场风险

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| 大厂推出竞品 | 高 | 高 | 快速迭代、深耕垂直场景、建立社区壁垒 |
| AI检测技术升级导致去AI味失效 | 中 | 中 | 持续跟踪检测技术、多策略应对 |
| 用户对AI写作接受度低 | 低 | 高 | 强调"人机共创"定位、教育市场 |

### 11.4 合规风险

| 风险 | 概率 | 影响 | 应对策略 |

# 自动化测试方案

## 1. 测试概述

### 1.1 测试目标

- 验证登录、注册、项目管理等核心功能的正确性
- 确保所有页面能够正常渲染和交互
- 提供完整的测试报告和截图证据
- 建立标准化的测试流程

### 1.2 测试范围

- 认证模块：登录页面、注册页面
- 项目管理模块：项目列表页面、新建项目功能
- 写作工作台模块：编辑器、章节导航

## 2. 测试环境

### 2.1 技术栈

- **测试框架**: Playwright
- **测试语言**: TypeScript
- **测试报告**: HTML + JSON
- **Mock 服务**: MSW (Mock Service Worker)

### 2.2 环境配置

- **基础 URL**: http://localhost:3000
- **测试超时**: 60秒
- **Web 服务器超时**: 30秒
- **截图策略**: 自动截图（on）
- **视频录制**: 自动录制（on）

## 3. 测试策略

### 3.1 截图策略

1. **自动截图**:
   - 每个测试用例执行时自动截图
   - 测试失败时自动截图
   - 截图保存在 `test-results` 目录

2. **手动截图**:
   - 关键步骤手动截图，与测试步骤绑定
   - 截图命名格式: `{test-case}-{step}-{timestamp}.png`
   - 截图包含在测试报告中

### 3.2 超时设置

- **全局测试超时**: 60秒
- **Web 服务器启动超时**: 30秒
- **单个操作超时**: 10秒

### 3.3 测试执行顺序

1. 认证模块测试
2. 项目管理模块测试
3. 写作工作台模块测试

## 5. 测试执行流程

### 5.1 前置条件

1. 启动开发服务器: `npm run dev`
2. 初始化 Mock 服务: `npx msw init public`
3. 确保所有依赖项已安装: `npm install`

### 5.2 执行命令

```bash
# 运行所有测试
npx playwright test

# 运行特定模块测试
npx playwright test tests/e2e/auth
npx playwright test tests/e2e/projects
npx playwright test tests/e2e/workbench

# 查看测试报告
npx playwright show-report
```

### 5.3 测试报告

- **HTML 报告**: `playwright-report/index.html`
- **JSON 报告**: `test-results/results.json`
- **截图**: `test-results/screenshots/`
- **视频**: `test-results/videos/`

## 6. 故障处理

### 6.1 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| Mock 服务未启动 | 缺少 mockServiceWorker.js | 运行 `npx msw init public` |
| 组件未找到 | 缺少 UI 组件 | 检查并创建缺失的组件 |
| 测试超时 | 网络延迟或页面加载慢 | 检查网络连接，增加超时时间 |
| 截图未生成 | 配置问题 | 检查 Playwright 配置中的截图设置 |

### 6.2 错误分析

1. 查看测试报告中的错误信息
2. 检查截图和视频了解失败原因
3. 查看控制台日志获取详细错误
4. 修复问题后重新运行测试

## 7. 持续集成

### 7.1 CI 配置

在 CI 环境中，建议添加以下步骤：

1. 安装依赖: `npm install`
2. 初始化 Mock 服务: `npx msw init public`
3. 运行测试: `npx playwright test`
4. 上传测试报告和截图作为 artifacts

### 7.2 测试覆盖率

- 定期运行全量测试
- 监控测试覆盖率
- 为新功能添加测试用例

## 8. 结论

本测试方案确保了自动化测试的标准化和可重复性，通过详细的测试步骤和截图策略，为项目质量提供了有力保障。在执行测试时，应严格按照本方案的要求进行，确保测试结果的准确性和可靠性。
